# Safari 复制修复 · 设计

> 详细实测数据见本仓:[字体混淆还原-字体文件解析方案.md](字体混淆还原-字体文件解析方案.md)。
> 本文只讲**架构与关键取舍**。

## 问题

某些考试网站(学习通等)给题目文字挂了自定义字体,并把 DOM 里的字符替换成生僻字。
浏览器查字体画出的是**正常字形**,但复制走的是 **DOM 里的码位** → 复制出来是一串生僻字。

要还原,必须知道:**某个密文码位对应哪个字**。

## 关键洞察

加密字体文件本身**就是那份对照表**,只是藏成了字形:

- 字体文件里,U+5795 指向第 23 号字形
- 第 23 号字形的轮廓,是「目」的轮廓(站点重绘过,不是逐点相同)

所以还原路径是:**拿到字体 → 取轮廓 → 跟参考字库比对 → 得出码位↔字符的表**。

## 数据流

```
页面(注入的守卫)
  selectionchange
    → 按字体作用域分组(同一段文字可能混着普通字体与加密字体)
    → 上报:作用域、字符集合、该作用域的 @font-face 字体文件(base64 或 URL)
  copy(window 捕获阶段)
    → **当场**按当前选区把文字拆成**逐个文本节点**的片段(不依赖采集缓存,见 ADR-0005)
    → 每段带**自己的**作用域(按出现位置,不按字符身份,见 ADR-0006)
    → 逐段查自己的映射表 → setData('text/plain', 修复后) + preventDefault
                    ↑
主进程(engine.js)
  解析字体(opentype.js) → 逐码位栅格化(48×48、4bit) → 与 Noto Sans SC(GBK 全集)参考库最近邻匹配
  → 自身距离 ≥0.15 才算"确实被重映射" → 出映射表 → 下发给页面
```

## 查表要两步

守卫查表需要两样东西,缺一不可:

| 需要什么 | 从哪来 | 会不会过时 |
| --- | --- | --- |
| 这个字**画成了哪个字**(码位→明文) | 主进程下发的映射表 | 不会 —— 按字体整份下发,与选区无关 |
| 这个字**属于哪个字体作用域** | 页面现算 | 复制时当场算,不缓存 |

第二样曾经是采集缓存(`charScopes`),于是出现了一个竞态:
采集比复制慢一拍,**刚选到、还没采集过的密文字查表落空 → 原样进剪贴板**。
真实表现是"前半句修好了、后半句还是密文"(前半句早先选过、缓存里有)。
现在改为复制时当场从 DOM 现算(ADR-0005),这个竞态消失。

作用域 key 里含**字体内容指纹**:站点换字体 → 换作用域 → 重新建映射,
不会拿旧字体的表去套新字体。

## 关键取舍

| 取舍 | 决定 | 理由 |
| --- | --- | --- |
| 识别放页面还是主进程 | **主进程** | 页面 canvas 的栅格化器与参考库不同,相似度只有 0.87~0.97,「专」会判成「令」 |
| 映射粒度 | **按字体**(整份码位表) | 按选区建的话,扩大选区后新字全是乱码(见 ADR-0002) |
| 什么时候建映射 | **预热**:装好就扫本页自定义字体 | 刚切到标签就复制也能修好,不用等 |
| 目标范围 | **按站点 URL 覆盖所有相关标签** | 只管前台标签会在换题/切标签时失效 |
| 识别不出怎么办 | **不改** | 宁可留怪字,不写错字 |
| 参考字体选哪个 | Noto Sans SC(与站点底稿同字型) | 换成宋体,「国」就判不出来 |
| 参考库覆盖多少字 | **GBK 全集**(21526 字,gzip 9.7MB) | 只含 GB2312 时,库里缺的生僻字会被认成形近的错字(燚→焱) |
| 作用域什么时候算 | **复制时当场算** | 采集缓存会慢一拍,新选区的字查表落空(见 ADR-0005) |

## 三道闸门 + 一条先验

1. **自身距离 ≥ 0.15**:证明这个码位确实被画成了别的字(普通字体的自身距离只有 0.02~0.05,直接被挡)
2. **相似度 ≥ 0.8、margin ≥ 0.01**:分不清就不改
3. **字体级拟合率 ≥ 0.7**:图标字体(icomoon/VideoJS)偶尔有一个字形像汉字,整体拟合率只有 3% → 整个字体判为普通字体,不做映射
4. **常用字先验**(加分 0.02,参与 margin 计算):偏旁相同的字像素上分不开
   (格 0.8496 vs 挌 0.8472),但字频分得开 → 常用字加分。
   两个都是常用字(己/已/巳、略/赂)→ 加分抵消 → 仍然不改。

## 判不出来的字怎么办

站点把字形**重绘**过,有些字重绘后像素上更接近另一个字
(实测:「坉」该是「略」,但重绘后离「赂」更近:0.1007 vs 0.1162,
且 48/64/96 三档分辨率都一样)。**像素里没有答案,任何度量都选不对**。

这种情况只能靠**语境**(「战X管理能力」→ 战略)——即设计文档里提过的
"大模型做上下文消歧",本版未做。当前的行为是**保守不改**:
剪贴板里留那个密文码位(宁可留密文,也不写错字)。

## 已知边界

- 跨源 iframe:注入被同源策略拦,copy 事件也不跨 frame 冒泡 → 无解
- @font-face 在跨源样式表里:页面读不到 → 该作用域不还原(可由主进程按 URL 兜底下载,本版未做)
- 明文含 GB2312 之外的生僻字:参考库覆盖不到 → 该字保持原样
