# ADR-0006:查表按"出现位置"判定,而不是按"字符身份"

- 状态:已定
- 日期:2026-10-21
- 相关:ADR-0002(映射按字体建)、ADR-0005(复制时当场解析作用域)

## 背景

查表需要两样东西:

1. 这个字**画成了哪个字**(码位→明文)—— 主进程按字体整份下发,不会过时
2. 这个字**属于哪个字体作用域** —— 页面现算(ADR-0005)

ADR-0005 解决了"第 2 样要现算",但当时**第 2 样是按字符身份记的**:
一个全局的"字符 → 作用域"表,同一个字只对应一个作用域。

## 出问题的地方

混淆字体的**密文码位恰恰是常用字**(天/地/问/水/土…)。
于是同一个字在一次选区里可能出现两次:

| 出现位置 | DOM 里的字 | 字体 | 屏幕上显示 | 正确结果 |
| --- | --- | --- | --- | --- |
| 甲 | 天 | 混淆字体 | 人 | **人** |
| 乙 | 天 | 普通字体 | 天 | **天** |

按字符身份记作用域 → 两处只能有一个作用域:

- 混淆那处先出现 → 普通那处也被改成「人」→ **复制出错字** ✗
- 普通那处先出现 → 混淆那处没被还原 → 留密文(漏,安全但功能受损) ✗

实测(`generality.cjs` 用例 s2-obf-first,旧实现):

```
期望 = "人天"
实际 = "人人"      ← 普通那处被改错了
```

## 决定

**按出现位置判定**:把选区拆成**逐个文本节点**的片段,每段带自己的作用域,
逐段查自己的表、逐段替换,再按顺序拼回浏览器那份选区文本。

```
选区文本(浏览器渲染的那份,保留换行等排版)
  ↑ 按顺序对齐
片段1「天地玄黄」→ 作用域 A → 查 A 的表
片段2「普通文字」→ 作用域 B(无映射)→ 原样
片段3「宇宙洪荒」→ 作用域 A → 查 A 的表
```

要点:

- 对齐时**只比对非空白字符**:浏览器渲染的文本会按 CSS 折叠空白,
  而文本节点原文里带着制表符、缩进换行,直接比对必然对不上
  (实测:整页选中时第一段就断 → 整页都没还原)
- 对不上的部分**原样保留**(宁可留密文,也不猜)
- 输出骨架仍是浏览器那份 → 换行、缩进都保留

## 代价

- 复制时要多走一遍选区的文本节点(实测 < 1ms)
- 需要"片段 ↔ 选区文本"的对齐逻辑,比全局字符表复杂

## 验证

`src/features/safari-repair/test/generality.cjs`(7 个用例,全是"用户没给过"的场景):

| 用例 | 期望 | 说明 |
| --- | --- | --- |
| s1-plain-first | 天人 | 普通在前 + 密文在后 |
| s2-obf-first | 人天 | 密文在前 + 普通在后(旧实现这里是"人人") |
| s3-pure-obf | 人工智能正在改变世界科技 | 纯密文 |
| s4-pure-plain | 原样 | 纯普通文字一个字不动 |
| s5-mixed | 人工智能普通文字正在改变 | 密文与普通文字混在一段 |
| s6-two-fonts | 人工智能工智能正 | 同一个字在**两种混淆字体**里画成不同的字 |
| 整页一次选中 | 全部正确 | 最难组合:多作用域 + 同字跨作用域同时出现 |

真实站点(学习通测验页,目标页不在前台):164 字符、27 个密文码位**残留 0**,
剪贴板与"按映射替换后的期望文本"**逐字一致**。
