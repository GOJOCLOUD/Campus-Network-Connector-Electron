# ADR-0023:⌃D 的**优先级**靠**低级键盘钩子**(`WH_KEYBOARD_LL`)

- 状态:**已定**
- 日期:2026-10-27
- 相关:ADR-0021(Tauri 侧 ADR-0031:剪贴板直入的键位)、ADR-0017(Windows 线抢 ⌃D)
- 性质:定下 Windows 线 ⌃D 的**优先级**怎么保证。
- 谱系:Tauri 侧是**同一条决策**的 ADR-0033,两边行为一致。

---

## 一、问题(2026-10-27 真人反馈)

**在微信里**按 ⌃D,是**微信自己的动作**;我们的「读剪贴板并键入」不触发。
别的软件里按 ⌃D 一切正常。

⇒ 同一个键,换个软件就失灵 ⇒ 不是「有没有注册」的问题,是**谁先拿到**的问题。

## 二、查清楚了(不是猜)

| 检查 | 结果 | 说明 |
| --- | --- | --- |
| 启动日志 `[shortcut] Ctrl+D=true` | 注册**是好的** | 不是「被别的软件先注册」那种情况 |
| 本进程 `RegisterHotKey(Ctrl+D)` | 失败,err=**1409** | 组合键系统里有人占 —— 实测把我们退出后再调就拿到了 ⇒ 占用者**是我们自己** |
| 微信自己的 `RegisterHotKey` | 没占 | 我们注册成功时微信早就在跑了 ⇒ 它**没用系统热键** |

⇒ 微信走的是**低级键盘钩子**(`WH_KEYBOARD_LL`)。Windows 的输入顺序是

```text
低级钩子 → 系统热键 → 目标窗口
```

⇒ 微信在**系统热键之前**就把 Ctrl+D 处理掉(多半还吞掉)
⇒ 我们的 `WM_HOTKEY` **根本没来过**(日志里没有「⌃D 直输」那一行)。

**系统热键压不过低级钩子** —— 这是 Windows 的机制,没有别的办法绕。

## 三、决策:自己也装一个低级钩子,把 ⌃D 吞掉

Windows 的规则是**后安装的钩子先被调用** ⇒

- 我们装一个 `WH_KEYBOARD_LL`,看到 ⌃D 就**吞掉它**(返回 1);
- ⇒ 微信收不到、系统热键也收不到 ⇒ **只有我们响应**;
- 顺带的好处:系统热键那一路自然不会再来 ⇒ **不会重复触发**。

### 为什么不新增代价

我们本来就用系统全局热键把 ⌃D **系统级占住**了 ⇒ 按下去本来就不会送到前台软件
(Edge 的收藏夹之类的一直就不生效)。吞掉只是把「谁来处理」从系统热键换成我们的钩子。

### ⚠️ 诚实说明:这不是绝对保证

对方**后启动**的话,它的钩子会先被调用 ⇒ 我们就收不到。
这是 Windows 的机制,用户这边绕不过去。

⇒ 所以界面/日志要**如实**说「钩子装上了没有」,而不是笼统地说「优先级最高」。

### 钩子装不上怎么办

**如实降级**:还有系统热键那一路(能用,只是压不过用钩子的软件),
并且诊断里把「钩子没装上」写出来。

## 四、latch 不受影响

latch(触发一次之后必须**松开 Control** 才重新武装)仍然由**只读的** Control 观察器
负责(`GetAsyncKeyState` 轮询)—— 钩子只负责「认键」。
两个平台走的是**同一个** `fire()` 包装 / 同一份状态机,规则一字不改。

## 六、验收

- **门禁**:node --test tools/verify/verify-hotkey-priority.cjs
  - 源码层:原生模块里必须有真正的 `WH_KEYBOARD_LL` 钩子(装钩子 + 消息循环 + `return 1` 吞键),
    主进程必须真的去装它,「⌃D 抢到了没有」必须把钩子算进去;
  - 决策逻辑:带 Control 才触发、按住不放不重复触发;
  - (Tauri 侧还多一条:在 CI 的 Windows runner 上**真的装一次钩子**再摘掉
    —— 那几行原始 FFI 写错了编译也过、装的时候才炸,静态检查抓不到。)
- **诊断**:`native:getStatus` 的 `shortcutHookCtrlD` 能看出钩子装上了没有。
- **真机**:在**微信**里按 ⌃D ⇒ 我们的功能触发(微信收不到那个键)。
