# ADR-0014:打包白名单漏文件 ⇒ 装上即崩 —— 打包自检必须查「包内相对 require」

- 状态:已定(Electron / macOS 已修)
- 日期:2026-10-23
- 相关:ADR-0013(快捷键 ⌃S/⌃D + latch)、ADR-0003(原生模块必须 asarUnpack)

## 背景

用户装上 Electron 版后反馈「**打不开**」,截图是:

```
A JavaScript error occurred in the main process

Uncaught Exception:
Error: Cannot find module './shortcut-latch.cjs'
Require stack:
- /Applications/模拟输入.app/Contents/Resources/app.asar/main.js
```

一开始怀疑是「另一个版本正在运行」(两个 App 的 bundle ID 与单实例锁都是各自的,
而且 macOS 上 Tauri 走自建事件 tap、**不注册系统全局热键** ⇒ 互不冲突)。
**不是。** 真因在打包那一步。

---

## 一、根因:`build.files` 是**白名单**,而它从项目第一个提交起再没改过

`electron-builder` 的 `build.files` 一旦写出来就是**白名单**:只有列进去的
路径才会进包。仓库根目录新增的纯函数模块不在里面:

| 模块 | 什么时候加的 | 干什么 |
| --- | --- | --- |
| `playback-guard.cjs` | 2026-10-23 18:48(T0 修复) | 回放两道安全闸(重入保护 + 排除自己窗口) |
| `shortcut-latch.cjs` | 2026-10-23 本轮(⌃S/⌃D 的 latch) | 快捷键的触发许可状态机 |

⇒ **两个都没进包** ⇒ `main.js` **顶层**的 `require(...)` 直接抛 ⇒
**启动即崩**(窗口永远出不来)。

### ⚠️ 连带发现:从 18:48 起发布的包就是坏的

`playback-guard.cjs` 的 `require` 也在 `main.js` 顶层 ⇒
**2026-10-23 18:48 那次 T0 修复之后的每一个 Electron 包,装上启动都是崩的**,
而 **CI 一直绿**。

⇒ 那些包里"回放两道安全闸"也等于**没有** —— 一装上就崩,根本走不到回放。

---

## 二、为什么 CI 抓不到

当时的打包自检(`tools/verify/verify-package.cjs`)只查:

- 原生模块有没有解包到 `app.asar.unpacked`、能不能加载;
- Safari 修复的运行时文件在不在 asar 里;
- vendor 里的参考库在不在;
- asar 里**不该**有的目录(测试/文档/算法源码)有没有混进去。

**没有一条**是"主进程 require 的东西在不在包里" ⇒
**漏打包这一类问题,它根本看不见**。

> 这也是为什么「CI 绿」不等于「装上能用」:门禁查的是**它知道要查的东西**。

---

## 三、修法

### ① `build.files` 加 `"*.cjs"`

根目录的 `.cjs` 全部进包(工具目录 `tools/**` 仍然被 `!tools/**/*` 排除)。

### ② 打包自检新增**硬门禁**:包内所有相对 require 都必须能解析

把 asar 解出来 → 扫所有 `.js` / `.cjs` / `.mjs` 里的**字面量相对 require**
(`require('./xxx')`)→ 逐个验证能不能解析到:

- 原样 → 补 `.js` / `.cjs` / `.json` → 当目录找 `index.*`;
- 解包到 `app.asar.unpacked` 的原生模块也算存在(asar 里只存占位);
- `node_modules/` 不扫(第三方依赖的**可选依赖**常常没被打进去,扫了会误报);
- 计算路径的 require(`require(变量)`)静态查不了,跳过
  (例如 `mac-coregraphics/index.js` 里的 `require(binding)`)。

**缺一个就判失败** ⇒ 漏打包在**打包那一刻**就被拦下,而不是等用户装上。

---

## 四、验证(门禁有判别力)

| 步骤 | 结果 |
| --- | --- |
| 新门禁对**旧的坏包**跑 | ❌ 红,点名缺 `main.js → ./shortcut-latch.cjs` 与 `main.js → ./playback-guard.cjs` ⇒ **证明这条检查真能抓住这类问题** |
| 修完重建再跑 | ✅ 绿(扫了 18 个文件) |
| 装上启动 | 主进程 + **渲染进程**都在(窗口建出来了),没有崩溃对话框 |
| 运行时日志 | `[shortcut] Ctrl+S=true Ctrl+D=true latch=true` |

---

## 五、Tauri 线有没有这个问题

**没有。** Tauri 用 `tauri.conf.json` 的 `frontendDist` **整包拷贝**,
没有白名单 ⇒ 新增前端文件不会漏。

但两边的教训一样:**新增根目录模块 ⇒ 必须同步加进打包白名单**。
(白名单是一种**隐式契约**,没有任何机制会提醒你它存在 —— 这就是本条 ADR 存在的理由。)

---

## 六、教训

**「CI 绿」不等于「装上能用」。** 门禁只能查它**知道要查**的东西;
没写进去的失败模式,再绿的流水线也看不见。
⇒ 每次新增一类"装上才暴露"的风险,都要**同时补一条门禁**。

**打包白名单是隐式契约。** 改 `package.json` 的 `files` 时,
必须把"仓库根目录新增了哪些文件"一起检查一遍。

**先看错误原文,别先猜。** 「另一个版本在运行」是一个很自然的猜测,
但两个 App 的 bundle ID、单实例锁、全局热键三条路都不相干 ——
看一眼错误框里的 `Cannot find module './xxx'` 就能立刻排除掉一大类猜测。
