# ADR-0017:浏览器修复的两个根因 —— 渲染必须在**页面主世界** + 栅格必须**等于参考库**

- 状态:**已定**(2026-10-25 用户反馈「浏览器修复是失效的」后定位并修掉)
- 日期:2026-10-25
- 相关:ADR-0013(Windows 线与 macOS 线行为对齐)、ADR-0014(打包白名单漏文件,装上即崩)
- 性质:定下**字形匹配链路**的两条不变量 —— 这两条错了,功能**静默失能**(不报错、界面看不出)。
- 谱系:Tauri 侧同一条决策是 **ADR-0027**;Windows 线在同仓是 **ADR-0018**。

---

## 一句话

扩展一直是坏的,只是**没人验证过它**:e2e 用例指向一个不存在的目录,从来没跑过。

修好它要同时改**两处**,少一处都不行:

1. **字形渲染必须在页面主世界做** —— 扩展的隔离世界拿不到页面的 `@font-face`。
2. **渲染的栅格尺寸必须等于参考字形库的栅格尺寸** —— 浏览器送 32×32、库是 48×48,位图与字形错位。

---

## 决策一:字形渲染搬到页面主世界

### 背景

浏览器的扩展内容脚本跑在**隔离世界**(isolated world)里 —— 和页面脚本共享 DOM,
但**不共享 JS 环境**,也不共享页面的样式与字体环境。

2026-10-25 实测(Chromium,仓库自带的字体混淆夹具):

| 上下文 | `document.fonts` | canvas 画「ObfA」的结果 |
| --- | --- | --- |
| 页面**主世界** | 有(`ObfA:loaded`) | 与缺省字体**不同** ⇒ 字体可用 |
| 扩展**隔离世界** | **空** | 与「一个不存在的字体」**逐像素相同** ⇒ 字体用不了 |

⇒ 隔离世界里 canvas 画出来的是**回退字体** ⇒ 字形的最近邻还是它自己
⇒ 判定「这个作用域没被混淆」⇒ **永远不还原**。

### 为什么 Mac 上没这个问题

Mac 那条路(Safari + Apple Events)执行的 JS **就在页面主世界里**
(`packages/browser-adapters/shared/src/page-agent.ts` 就是那么跑的)
⇒ 页面自己的字体当然可用。

⇒ 同一个机制搬到 Chromium 上,**必须把渲染也搬到主世界**,
不能只把「匹配」搬过去。

### 决策

- 隔离世界保留它**本来就可靠**的那部分:选区分析、向后台请求匹配、写剪贴板、
  INTENT 事件(这些由 e2e 用例 A/B 证明过是对的)。
- **只把字形渲染**经一条 DOM CustomEvent 桥搬到主世界:
  - 隔离世界 → 主世界:`copy-repair:render-request`(带随机 token + 自增 id + 一个作用域的一批字符)
  - 主世界 → 隔离世界:`copy-repair:render-response`(原样带回 token / id / signature / items)
- 主世界 **3 秒**没应答 ⇒ 当作**空结果** ⇒ 这一轮**一个字符都不替换**
  —— **宁可不改,不可写错字**。
- 这条通道**不是安全边界**(页面脚本看得见、也能伪造响应)。只在本机运行、
  只影响剪贴板内容,按「够用且可审计」处理:随机 token + 响应必须原样带回
  (挡的是串台,不是恶意页面)。这一点写在代码注释里。

### 门禁

`tools/verify/verify-chromium-extension.cjs` 里有一条断言盯的就是**渲染发生在哪个世界**:

- `content-main.js` 必须**装**渲染服务(有 `new GlyphRenderer`)
- `content-isolated.js` 必须**没有**渲染器(不许自己渲染)

⇒ 有人把渲染挪回隔离世界,门禁立刻红,不用等 e2e。

## 决策二:栅格尺寸必须等于参考库

### 背景

字形匹配的原理:浏览器把字符画成一张 **N×N 的覆盖度位图**,
匹配器拿这张位图与参考库里的字形**逐格**比较。

- 浏览器侧:`GlyphRenderer` 的栅格边长
- 参考库侧:CRDB 二进制头里的 `gridSize`

**这两个数字分属两个文件,没有任何东西保证它们相等。**

仓库里的实际值:**渲染器 32×32、参考库 48×48**(参考库是 48 是有理由的:
`tools/build-vendor.mjs` 里写着「48×48 才能分清『国/固』这类方框字,
32×32 实测会判不出」)。

### 错位之后的实测(2026-10-25)

送进匹配器的位图只有 32×32,而库里是 48×48 ⇒ 两张图**错位**:

| 字符 | 最近邻 | score | margin | selfDistance |
| --- | --- | --- | --- | --- |
| 天 | ‵ | 0.928 | **0** | 0.269 |
| 地 | ﹊ | 0.917 | **0.001** | 0.312 |
| 玄 | 爫 | 0.863 | **0** | 0.303 |

⇒ 最近邻落到「爫」「﹊」这类**冷僻符号**上,`margin` 几乎为 0
⇒ `isConfidentSubstitution` 的四条判据里「次优差距」这条过不去
⇒ 永远不替换 ⇒ **复制出来还是密文**。

⇒ 关键点:**这个错位不产生任何报错**,界面也不会提示什么 ——
它只是「功能没生效」,是最难查的一类故障。

### 决策

- 栅格尺寸收敛成**一个常量**:`packages/core/src/glyph-matching/grid.ts` 的
  `REFERENCE_GRID_SIZE = 48`。
- 渲染器**不许写死数字**:`new GlyphRenderer(REFERENCE_GRID_SIZE)`。
- 参考库构建脚本的默认 `--size` 也改成 48
  (以前是 32 ⇒ 谁不带参数跑一次,就造出一份对不上的库)。
- **门禁**:`tools/verify/verify-glyph-grid.cjs` 三条断言 ——
  库头里的 `gridSize` == 常量、源码里没有写死的 `new GlyphRenderer(数字)`、
  构建脚本的默认 `--size` == 常量。

## 决策三:修 e2e 用例本身的路径漂移

`tests/e2e/copy-repair.test.ts` 里扩展目录写的是 `dist/chromium`,
而构建脚本输出到 **`dist-core/chromium`**(`dist/` 是 vite 的前端产物目录)
⇒ 这条用例**从来没跑通过**。

⇒ 「扩展到底能不能把密文还原成明文」这件事,**从来没人验证过**。
⇒ 本轮修好路径后跑出来的真实结果是:**6 个用例 2 过 4 挂**,
修完上面两处才是 6/6。

⇒ 结论:**门禁不是「配了就有用」,是要真的跑起来**。
本次三道新门禁都做了**变异自检**(把根因改回去 → 门禁必须红 → 还原 → 必须绿)。

## 影响面

- `packages/browser-adapters/shared/src/render/main-world-renderer.ts`(**新增**):主世界渲染桥
- `packages/browser-adapters/shared/src/content-runtime.ts`:渲染改成走桥
- `packages/browser-adapters/shared/src/render/glyph-renderer.ts`:栅格取常量;fallback 对照组字号改成与目标一致
  (以前对照组是 32px、目标是 128px ⇒ 字号不同 ⇒ 「字体根本不存在」也会被判成不是 fallback)
- `packages/browser-adapters/shared/src/page-agent.ts`:栅格取常量
- `packages/core/src/glyph-matching/grid.ts`(**新增**):`REFERENCE_GRID_SIZE`
- `apps/chromium-extension/src/content-main.ts` / `apps/safari-extension/src/content-main.ts`:装上主世界渲染服务
- `tools/verify/verify-glyph-grid.cjs`(**新增**)、`tools/verify/verify-chromium-extension.cjs`(**新增到 mac 仓**)

## 谱系与「互不回流」

两个框架的仓库(`tauri` / `electron`)**各自**持有这份 `packages/` 代码,
本决策在两边**同时落地**(Tauri 侧 ADR-0027 / Electron 侧 ADR-0017),
**不从一边往另一边回流**。
Windows 线的「开关 + 自动注册」是另一条决策:
Tauri 侧 ADR-0028、Electron 侧 ADR-0018。
