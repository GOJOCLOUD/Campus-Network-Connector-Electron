**为什么改**(用户原话):

1. 「干脆直接把系统的抢了,我的软件优先级最高,这是最简单的办法,因为 Ctrl 加 D 我发现在普通桌面它是退出软件的功能,那在使用这个的时候没必要退出吧,所以说我就给他压制住」
2. 「你这个界面本来就有开始输入这个按钮,只不过给了你三秒来定位光标在哪?你现在多加个按钮进去,那跟普通的界面有什么区别?我现在就是要快捷键触发呀」
3. 「你加一个最小化,加一个关闭,加一个最大化,别他妈就只留小叉,让小叉变成放在后台,那不然人家真正想关软件还得点两次」
4. 「把全屏按钮给我删除掉,最小化保留,然后叉叉也保留,你能不能搞个终止按钮,搞个叉车,两个就重复了呀,现在就保留两个,一个最小化,一个终止,终止的形状要叉叉,其他的都不要」
5. 「你不要用ctrl+D了,直接ctrl+shift+D吧」
6. 「在一定时间内,三个按键只要同时按了就可以触发就行了,别搞了非常严格的顺序,或者说时间间隔特别短,这样太难触发了」
7. 「在windows上那个把密文转化成明文的那个功能是失效的,没有用的……最后个页面的相关提示也和macOS上面的两个版本完全不同,感觉完全就少了那个呃浏览器修复功能」

第 1 条是**认知的更正**:初版把「抢 ⌃D 会让用户的软件被关掉」当成了风险,于是干脆不抢;
但用户要的是**反过来** —— 把它抢过来,让那个软件**收不到**它,那个软件就不会被自己的「退出」关掉。
⇒ 风险不是「抢了会出事」,而是「**没抢到**才会出事」(见决策一)。

第 4~7 条同样是**用户直接改的口径**:

- 第 4 条把右上角**收敛到两个**:「关闭软件」(电源图标)与叉叉**重复** ⇒ 删掉;
  「最大化」按用户口径删掉;「放到后台」也删掉(窗口藏起来**仍然做得到**:
  Alt+F4 / 任务栏右键「关闭窗口」,回来靠**托盘**或再运行一次程序)。
- 第 5 条把键位从 ⌃D 换成 **⌃⇧D**:⌃D 在别的软件里是「退出」那一族,
  换成带 Shift 的组合,撞车概率低得多;而「压制住对方的退出」这件事
  **由「抢到注册」保证**,不由键位保证(见决策一)。
- 第 6 条把三键判定**放宽**:修饰键在 **2 秒窗口**内**按下过**就算数,
  **顺序不限**、可以已经松开 ⇒ 不再要求「严格顺序 + 极短间隔」。
- 第 7 条是**功能缺失**:Windows 上「把密文还原成明文」的能力**实际等于零**
  (扩展一直都在仓库里,但两个 Windows 安装包**都没带它**)⇒ 补上(见决策六)。

## 决策一:Windows 线抢 **⌃⇧D**(只抢这一个)

### 背景

- **⌃D 在普通 Windows 软件里常常是「退出软件」那一族动作**(菜单加速键)。
  用户正是在自己常用的软件里被它坑过:「Ctrl 加 D 我发现在普通桌面它是退出软件的功能」。
- 我们把它注册成**全局热键**(`globalShortcut.register('Ctrl+Shift+D')`)
  ⇒ 别的软件**收不到**它 ⇒ 用户在那个软件里按这个组合键,那个软件**不会被关掉**。
- **2026-10-25 第二次改口径:键位从 ⌃D 换成 ⌃⇧D**(用户原话:
  「你不要用ctrl+D了,直接ctrl+shift+D吧」)⇒ 与别的软件的撞车概率低得多;
  而「压制住对方的退出」这件事**由抢到注册**保证,不由键位保证。

### 决策

**注册 ⌃⇧D(读剪贴板并键入);不注册 ⌃S。**

| 层 | 之前(2026-10-24) | 现在 |
| --- | --- | --- |
| 系统全局热键 | 一个都不注册 | **只注册 `Ctrl+Shift+D`**(`registerShortcuts()`) |
| `Ctrl+S` | 不注册 | **仍然不注册**(理由见下) |
| 窗口内 keydown | 不拦 | 不拦(⌃S / ⌃⇧D 在**我们自己的窗口里**都是普通按键) |
| Control 观察器 | 不启动 | **启动**(`watchControlKey`)—— 它服务于 ⌃⇧D 的 latch |

**⌃S 为什么不抢**三条理由:

1. 它驱动的「默认执行(回放)」那一屏在 Windows 上**已经没有界面了**(ADR-0016)⇒ 抢了也没有东西可触发;
2. Ctrl+S 在别的软件里是「**保存**」⇒ 抢过来会把人家的保存弄坏;
3. 用户 2026-10-25 的原话只点名了**剪贴板直入那个键**(⌃D → 后改 ⌃⇧D)。

### 能不能真抢到:**不一定** —— 所以必须**看得见**

全局热键注册是**系统级独占**的:系统不会让两个进程同时拥有同一个组合键。
结果只有两种:**全拿到** 或 **全没有**(不存在「两个都收到」)。

| 对方是什么 | 结果 |
| --- | --- |
| **菜单加速键**(绝大多数软件的「退出」都是这种) | 我们的注册**先于**它生效 ⇒ **稳赢** |
| 对方也 `RegisterHotKey` 了同一个组合键、且**先注册** | **抢不到** |

抢不到时,有两件事**同时**成立,而且都跟用户有关:

1. 按 ⌃⇧D **不会触发我们**;
2. 目标软件自己的 Ctrl+Shift+D **照常生效** ⇒ 那个软件**还是会被它的「退出」关掉**。

⇒ 抢没抢到必须**变成看得见的事实**,不能让人以为「按了没反应」是系统的问题。

**看得见的三处**:

| 位置 | 内容 |
| --- | --- |
| 诊断字段 | `native:getStatus` 里新增 `shortcutPasteRegistered`(抢到了 = `true`)、`globalShortcutsEnabled` = `true` |
| 启动日志 | 注册失败时打一条警告:「⌃⇧D 没抢到(这个组合键被别的软件先注册了)…」 |
| **界面提示** | 抢不到时,「键盘输入」页出现一行**琥珀色提示**：「Ctrl+Shift+D 没抢到(这个组合键被别的软件先注册了):按它不会触发我们,目标软件自己的 Ctrl+Shift+D 也会照常生效。」 |

界面提示的判据是 `nativeStatus.shortcutPasteRegistered === false` —— 只有**明确抢不到**才提示;
抢到了**不**提示(别一上来就吓人)。

### latch 保留

⌃⇧D 仍然过 **latch**:触发一次之后必须**松开 Control** 才重新武装
(用户 2026-10-23 的要求:「触发之后 Ctrl+D 整个按键就不再会继续影响它了」——
  2026-10-25 键位改成 ⌃⇧D 之后,这条要求**照旧成立**:触发一次必须**松开 Control**
  才重新武装。)。
⇒ Control 按下/松开的**只读观察**必须开着(`win-input` 的 `watchControlKey`,
用 `GetAsyncKeyState(VK_CONTROL)` 每 25ms 轮询做边沿检测),否则按住 Ctrl 连按会把剪贴板**连着键入好几遍**。

选它而不是低级键盘钩子(`WH_KEYBOARD_LL`)的理由:读的是**物理键盘状态**,
**不受 `RegisterHotKey` 影响** ⇒ 组合键被别的程序抢走也照样拿得到边沿;
也没有 `LowLevelHooksTimeout` 的风险(丢一次边沿 = latch 解不开)。
拿不到观察源时**如实降级**(`latch=false` + 打 warn),**不假装 latch 生效了**。

状态机在 `shortcut-latch.cjs`(纯函数),回归测试见 `tools/verify/verify-shortcut-latch.cjs`。

### 门禁

- 界面门禁 `verify-ui-platforms.cjs` 的**源码级断言**(界面上看不出系统里注册了哪些键):
  查 `GLOBAL_SHORTCUTS_ENABLED = true`、查注册的是 `Ctrl+Shift+D`、
  查**没有**再注册 `Ctrl+D`、查**没有** `Ctrl+S`、
  查 `shortcutPasteRegistered` 这一栏。
- 界面门禁的**界面级断言**:桩里 `shortcutPasteRegistered: false` ⇒ 界面**必须**出现提示;
  `true` ⇒ 界面**必须没有**提示。

## 决策二:关窗口 = 藏起来,进程留着(托盘常驻)

### 背景

「点叉他就直接完全退出了」= 把 app **关掉了**,不是「收起来」。
用户要的是**后台挂着、功能依然生效**。

### 决策

| 动作 | 结果 |
| --- | --- |
| Alt+F4 / 任务栏右键「关闭窗口」 | **隐藏窗口**(`window:hide` → `mainWindow.hide()`),进程留着 |
| 系统级关闭(Alt+F4 / 任务栏右键→关闭窗口) | **同样只隐藏**,不退出 |
| 右上角**叉叉**(=「终止」) | **彻底退出**进程 —— **一次点击就退** |
| 左键点托盘图标 | 把窗口叫回来 |
| 托盘右键菜单 →「显示窗口」 | 把窗口叫回来 |
| 托盘右键菜单 →「退出程序」 | **彻底退出**进程 |
| 再运行一次程序 | 单实例回调 → 把窗口叫回来 |

系统级关闭**也只隐藏**,是为了跟 macOS 的红绿灯**同口径**(关窗口 ≠ 退出 App)。
⇒ 彻底退出有**两个**入口:右上角**叉叉**(一次点击)和托盘菜单的「退出程序」。
(2026-10-25 第二次改口径后,右上角那个「关闭软件」按钮已删 —— 它与叉叉重复。)

实现上靠一个 `isQuitting` 标志:`app.on('before-quit')` 会把它置 `true`,
`mainWindow.on('close')` 看到它就**放行**——否则会把退出锁死(自己拦自己)。

### 为什么必须有托盘

Windows 上窗口一藏,**任务栏就没有图标了** —— 没有托盘,这个 app **再也找不回来**
(只剩「再运行一次程序」那条路,而用户不一定知道 exe 在哪)。

### 实现

Electron 的 `Tray` 是**内置**的 ⇒ **零新增依赖**。

托盘图标必须是**真实文件路径**:Windows 的托盘是把图标交给系统画的(`Shell_NotifyIcon`),
系统读不了 asar ⇒ 打包时用 `extraResources` 把它放到 **asar 外面**
(`resources/win-icon.ico`),运行时从 `process.resourcesPath` 取;
开发时退回仓库里的 `build/win-icon.ico`。

托盘建不起来**不能拖垮 app**:托盘只是「找回窗口」的**便利**,
不是「后台活着」的必要条件(窗口只是被**隐藏**,进程照样活着)。
所以任何一步出错都只是**不装托盘**,并把原因写进日志(`[tray] ...`)。

## 决策三:右上角**两个**自绘按钮

**最小化 / 叉叉(=终止)。**

> 2026-10-25 第二次改口径:「把全屏按钮给我删除掉,最小化保留,然后叉叉也保留……
> 现在就保留两个,一个最小化,一个终止,终止的形状要叉叉,其他的都不要」
> ⇒ **最大化**、**关闭软件**(电源图标,与叉叉重复)、**放到后台**三个按钮**全部删掉**。

| 按钮 | 调什么 | 干什么 |
| --- | --- | --- |
| 最小化 | `window:minimize` | 窗口缩到任务栏 |
| **叉叉**(=「终止」) | `window:quit` | **彻底退出进程**,一次点击就退 |

> 「最大化」「关闭软件」(电源图标)「放到后台」三个按钮**已删**(2026-10-25 第二次改口径)。
> 它们各自的实现仍在源码里(`window:maximize` / `window:hide`),
> 但**界面上没有入口** ⇒ 将来要加回,接上就行。
| **关闭软件**(电源图标) | `window:quit` | **彻底退出进程**,一次点击就退 |
| **放到后台**(✕) | `window:hide` | 窗口藏起来、进程留着,功能继续生效 |

- Windows 是**无边框窗口**(`frame: false`),所以这四个是**页面自绘**的;
  macOS 仍用**原生红绿灯**,不变。
- 「最大化」是**切换**:`isMaximized() ? unmaximize() : maximize()`。
- 两个按钮挂在 `Stepper` 的 `corner` 位置(`app-nodrag`,不触发拖窗)。
- ⚠️ **叉叉就是退出**(2026-10-25 第二次改口径后的口径):
  它调 `quit`,**一次点击真退出**,不再有「放到后台」那一档。
  ⇒ 想把窗口藏起来、进程留着,用 **Alt+F4 / 任务栏右键「关闭窗口」**,
  回来靠**托盘图标**(左键)或再运行一次程序。

## 决策四:「读剪贴板并键入」的入口回到 **⌃⇧D**(界面上**不**再有那个按钮)

2026-10-24 曾把这个能力搬成界面按钮;2026-10-25 用户**撤回**了:

> 「你这个界面本来就有开始输入这个按钮,只不过给了你三秒来定位光标在哪?
> 你现在多加个按钮进去,那跟普通的界面有什么区别?**我现在就是要快捷键触发呀**」

⇒ 界面上「键盘输入」页现在只有「**开始输入（3s 后键入）**」和「**清空**」两个按钮,
**没有**「从剪贴板读入并键入」。

- 读剪贴板走**原生**通道(Electron `clipboard`),
  **不用** `navigator.clipboard.readText()` —— WebView2 里那个会因为焦点/权限直接失败。
- ⌃⇧D 触发时**立刻键入**(不倒计时)—— 理由见决策五。

## 决策五:「立刻键入」和「等 3 秒」是两种语义,不能混

### 背景

**点我们按钮的那一刻,焦点在「我们自己的窗口」里。**
立刻键入 ⇒ `sendText` 把字送进**我们自己的界面**(webview 里焦点所在的元素),
而不是用户想输入的那个目标软件。字就丢了。

两个框架对「立刻键入」的处理本来还不一致:
Electron 是 `if (delaySeconds > 0)`(显式 0 = 真的立刻),
Tauri 的桥接层写的是 `Number(delaySeconds || 3)` —— `0 || 3` = **3**,
**一个 bug 正好挡住了另一个 bug**。

### 决策

- **按钮路径一律等 3 秒**:「开始输入（3s 后键入）」走 `requestPinyinInput`,
  界面上同时给出「3 秒后开始输入,请将光标移动到目标位置」。
- **全局快捷键路径(⌃⇧D)立刻键入**:它是**目标软件在前台**时按的,焦点本来就在那边
  ⇒ 立刻键入是对的(这也是原来 ⌃D 传 0 的原因)。
- Tauri 侧的 `|| 3` 改成 `??`(显式 0 就是 0)⇒ 两边对「立刻」的口径一致。

### 门禁

- 界面门禁断言:「开始输入」触发的 `pinyinInput` 收到的**延迟是 3**(不是 0),
  且界面上有倒计时提示。(旧实现传 0 ⇒ 这两条断言会转红。)

## 决策六:Windows 的「浏览器修复」= 交付一个 **Chromium 扩展**

### 背景:能力不是"没写",是**没发出去**

用户 2026-10-25 的反馈:「在windows上那个把密文转化成明文的那个功能是失效的,没有用的,
和macOS同步的地方很少,感觉像是一个很老很老的版本,最后个页面的相关提示也和macOS上面的
两个版本完全不同,感觉完全就少了那个呃浏览器修复功能,你是不是就没搞上去?」

查证结果:

| 事实 | 证据 |
| --- | --- |
| 扩展**一直都在**仓库里 | `apps/chromium-extension/`(MV3、自带 10.2MB 字形库、**独立可运行**) |
| 但**两个 Windows 安装包都没有它** | Tauri `bundle.resources` 只带 `resources/glyph-db-48.crdb.gz`;Electron `build.extraResources` 只带 `build/win-icon.ico` |
| ⇒ Windows 上这条能力**实际等于零** | 桌面前端的功能清单在 Windows 上**故意返回空**(注释写「Windows 的浏览器字体纠正走 Chrome/Edge 扩展」) |
| macOS 上同一条能力是**原生**的 | Safari + Apple Events(ADR-0012 的平台范围)⇒ 界面上是一个**开关** |

### 为什么**不能**在 Windows 上照搬 mac 的做法

mac 的「Safari 复制修复」是**原生通道**:Apple Events 驱动 Safari 的 JS。
Windows 上**没有 Safari、没有 osascript、没有 Apple Events**,
而且桌面前端**根本管不了浏览器里的页面**(没有可注入的页面守卫通道)⇒
**给一个开关是骗人**:拨了也不会有任何事发生。

⇒ 正解只有一个:**那个能力由扩展提供**,而扩展**独立可运行**、不依赖桌面程序。

### 决策

1. **交付扩展**,两条路都走:
   - 桌面交付包 `模拟输入-Windows-全部.zip` **顶层**多一个 `browser-extension/` 文件夹
     (和两个安装程序放在一起),README-Install.txt 写清装法;
   - CI 的 release **额外发一个附件** `browser-extension-chromium.zip`
     (只下了 .exe 的用户也能拿到)。
2. **界面上给「说明块」,不给开关** —— 位置与 mac 的「Safari 复制修复」开关
   **完全相同**(最后一页的最上面),内容写清楚:由谁提供 / 去哪拿 / 怎么装。
3. **CI 门禁**:扩展必须**构建得出来**且**产物齐**
   (`tools/verify/verify-chromium-extension.cjs`):manifest 是合法 MV3、
   三个脚本不是空壳、字形库**能解开**(坏 gzip ⇒ 扩展静默失能:
   后台拿不到参考字形 ⇒ 还原不出明文 ⇒ 用户看到的就是「没反应」)。
4. **交付包自检**:出包前对着 **zip 内容**查
   `browser-extension/manifest.json` 等 5 个文件 + README
   (查暂存目录不够 —— 暂存目录里有、zip 里没有是打包环节漏掉的最常见形态)。

### 已知限制(必须写进文档,不能装作没有)

- Chrome 的「加载已解压的扩展程序」是**按路径引用**那个文件夹的 ⇒
  文件夹被删/被移动,扩展就失效 ⇒ README 明确建议**先复制到固定位置再加载**。
- Chrome **不允许**程序静默安装扩展(要么企业策略,要么用户手动加载)⇒
  这一步**必须用户自己做**,桌面程序替代不了。

## 验收

- **界面**(Windows,`tools/verify/verify-ui-platforms.cjs`):
  - 右上角**只有 2 个按钮**,且依次是「最小化 / 终止」;
  - 点这两个按钮,分别调的是 `minimize` / **`quit`**;
  - 右上角**不再有** `hide`(放到后台)那个按钮(用户明令删掉);
  - 界面上**没有**「从剪贴板读入并键入」按钮,「开始输入（3s 后键入）」还在;
  - 点「开始输入」⇒ 内容进键入通道,延迟是 **3**,界面有倒计时提示;
  - 桩里 `shortcutPasteRegistered: false` ⇒ 界面**出现**「没抢到」提示;
    `true` ⇒ 界面**没有**那条提示。
- **源码级**:全局快捷键的开关是**开**的;注册的是 `Ctrl+Shift+D`;**没有**再注册 `Ctrl+D`;
  **没有**注册 `Ctrl+S`;原生状态里有 `shortcutPasteRegistered` 这一栏。
- **latch**:`tools/verify/verify-shortcut-latch.cjs` 等 6 个脚本
  (`node --test`,共 37 条)全绿。
- **macOS 线**:界面仍是 4 步、仍用原生红绿灯;
  ⌃⇧D / ⌃S 的**键位两边一致**(2026-10-25 第二次改口径时,用户要求
  「MAc上也改成一模一样的」)。
- 两线各跑各的自检,各发各的包;**一边的绿不替另一边背书**。
- ⚠️ **Windows 真机行为仍未经真机验证**(本仓库的验证环境是 macOS)。
  CI 只证明「编得过 + 门禁过」。下面这些都要在 Windows 真机上过一遍:
  - ⌃⇧D 到底**抢没抢到**(界面提示会直接告诉你);
  - 按 ⌃⇧D 时目标软件**不被退出**、我们的功能**触发**;
  - 点叉叉 ⇒ 进程**真没了**(一次点击);
  - Alt+F4 ⇒ 窗口消失、托盘有图标、左键点它窗口回来。

## 范围与没做的

- 本 ADR **只改 Windows 线**(`win` 分支)。macOS 线只跟着改**键位**
  (⌃D → ⌃⇧D,用户明令「MAc上也改成一模一样的」)。
- **Windows 上现在只抢 ⌃⇧D 这一个全局键**。以后要加别的键,键位由用户拍板,
  并且必须是**不与系统默认键冲突**的组合。
- 「从剪贴板读入并键入」这个**按钮**只在 Windows 线撤掉(macOS 线的 ⌃⇧D 还在,不需要)。
- **darwin-only 的死代码不同步**:`src/features/safari-repair/*` 在 Windows 上
  永远不会被 require(功能注册表按 `platforms: ['darwin']` 过滤),
  同步它只会给 Windows 产品线塞一堆用不到的 macOS 代码 ⇒ **有意不同步**。
- ⌃S 的实现本体 `triggerDefaultExecute` **留着**但**没有入口**
  (Windows 线不注册 ⌃S、那一屏也撤了)⇒ 将来要加回 ⌃S,注册它就行,不用从头写。
  ESLint 因此报「定义了没用到」,已用 `eslint-disable-next-line no-unused-vars` **显式标注**:
  这是**故意**的,不是漏网。
