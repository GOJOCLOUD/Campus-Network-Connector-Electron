# ADR-0026:右上角按钮点不动、浏览器标签页越滚越多、那一栏说明要短

- 状态:**已定**
- 日期:2026-10-27
- 用户原话(2026-10-27 20:26):
  > 「没有丝毫修复，至少electron版本是这样的，右上角的缩小，最小化按钮，以及关闭按钮，完全就无法生效，然后打开浏览器这一这个界面说明太详细了，看起来乱七八糟的，不够简短，然后很严重的问题是一旦点击这个东西。它就会打开，不断的拉起浏览器，然后浏览器里面的页面超级多，而且这个浏览器根本就是无法使用的状态」
- 相关:ADR-0024(反反复复拉起浏览器)、ADR-0025(两个版本一眼分清)、ADR-0022(先找再起)
- 谱系:Tauri 侧是**同一条决策**的 ADR-0036,两边行为一致。

## 一、三个问题,三个根因(全部真机取证,不是猜的)

### 1. 右上角「最小化 / 叉叉」完全点不动 —— **拖拽区把真实鼠标点击吃了**

**现象**:窗口右上角那两个按钮按下去毫无反应。

**取证过程**(装了 Electron 版 + 开 `--remote-debugging-port` 进渲染器):

| 步骤 | 结果 |
| --- | --- |
| `window.cnc.minimize()` 直接调 | **有效**(窗口真的最小化了)⇒ IPC 链路没问题 |
| CDP 派发 `Input.dispatchMouseEvent` 点按钮 | **有效** ⇒ React 的 `onClick` 没问题 |
| **真实鼠标点击**(系统级 `mouse_event`)点按钮 | **无效** ⇒ 问题在「系统鼠标事件 → 渲染器」这一段 |
| 真实鼠标点击文本框 | **有效**(能获得焦点) ⇒ 系统点击确实能进到窗口 |
| 把根容器的 `app-drag` 去掉后再真实点击 | **有效** ⇒ 锁定在拖拽区 |

**根因**:`Stepper` 里「步骤圈 + 进度线」那一行带 `app-drag`:

```jsx
<div className={`${stepContainerClassName} app-drag flex w-full items-center p-8`}>
```

这一行的**矩形横跨整张卡片**,右上角正好压在窗口按钮上面。

Chromium 的拖拽区是**按矩形**算的:`no-drag` 只有在**这个元素是拖拽元素的子孙**时
才会把那块地方「挖空」。而窗口按钮那个容器(`corner`,`absolute top-3 right-3`)
是那一行的**兄弟**,不是子孙 ⇒ **挖不空**
⇒ 浏览器进程把真实鼠标的按下当成了「拖窗口」⇒ **点击根本进不到渲染器**。

> **为什么源码看着没问题**:CDP 伪造的点击是直接派发给渲染器的,
> **绕过了浏览器进程的拖拽区判定** ⇒ 门禁/脚本用 CDP 点一下是好的,
> 只有**真人用鼠标点**才会暴露。
> 也因此:`app-nodrag`、`button { no-drag }` 这些都**已经写对了**,
> 光看 CSS 完全看不出问题。

**决策**:「步骤圈那一行」**不再声明拖拽区**。根容器的 `app-drag` 矩形本来就覆盖
整个窗口(那一行是根容器的子孙)⇒ 那一行照样能拖窗口,**手感不变**;
而右上角按钮的容器是根容器的**子孙** ⇒ `no-drag` 这时能正常挖空 ⇒ 点击进得去。

### 2. 点开关就**不断拉起浏览器、页面越积越多** —— `--restore-last-session` 的指数级放大

**真机复现**(2026-10-27 20:47,已装的 Electron 版):

```
[12:47:51] edgeProcs=17 devtoolsLaunches=11 port=64316 targets=10
[12:47:53] edgeProcs=21 devtoolsLaunches=11 port=64316 targets=14
[12:47:56] edgeProcs=24 devtoolsLaunches=11 port=64316 targets=17
[12:47:58] edgeProcs=28 devtoolsLaunches=11 port=64316 targets=21
[12:48:01] edgeProcs=29 devtoolsLaunches=11 port=64316 targets=22   ← 稳住了
```

标签页清单(`Target.getTargets`):

```
21x  about:blank
 1x  https://www.chaoxing.com/
```

**根因(三条叠加)**:

1. **`--restore-last-session`**(根因):启动参数里带着它 ⇒ 每次启动都把
   **上一次会话**的标签页全恢复出来;而上一次会话里又装着上次恢复出来的那些
   ⇒ 标签页**每启动一次就多一批**(实测:一次启动就恢复出 21 个 `about:blank`)。
2. 标签页一多 ⇒ 浏览器启动变慢 ⇒ 调试端口迟迟不开 ⇒ 被判定成「起不来」。
3. **连不上 CDP 不计失败次数**:`launchFailures` 在 `waitForEndpoint` 成功时就被
   清成 0,而 `CdpClient.connect()` 失败是**另一条路**抛出去的 ⇒ 失败次数永远不涨
   ⇒ 「起不来上限(3 次)」**形同虚设** ⇒ 每 4 秒重试一次、每次都再拉起一个浏览器。

**决策**(四条一起改):

| # | 改动 | 为什么 |
| --- | --- | --- |
| a | **去掉 `--restore-last-session`** | 标签页不再滚雪球。**不影响登录**——cookie / 密码在 profile 里,照样有效 |
| b | `CdpClient.connect()` 失败**也计入** `launchFailures` | 让「起不来上限」真的生效 |
| c | 已经有浏览器在跑、只是暂时连不上 ⇒ **不再起新的** | 同 profile 再起一个 = Chromium 的「转发启动」:新进程不开自己的调试端口,只是给已经在跑的那个**再开一个标签页** ⇒ 页面越积越多 |
| d | 起浏览器前先扫进程:连不上就**如实报错**、下一轮重试 | 不再默默拉起第二个浏览器 |

### 3. 那一栏说明太长

`description`(21 字)+ `hint`(57 字)+「浏览器已关闭」那一行(20 字)
叠在一起 ⇒ 那一栏变成三大段密密麻麻的字 ⇒ 用户原话「看起来乱七八糟的」。

**决策**:界面上只留**必须当下知道的一句**,细节挪到文档里:

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 功能说明 | 把被网页字体混淆的文字还原成你看到的那句话 | **还原网页里被混淆的文字** |
| 开关打开时的提示 | 本软件已打开一个自己的 Edge 窗口 —— ……（57 字） | **请在本软件开的 Edge 窗口里上网、答题** |
| 「浏览器已关闭」 | 浏览器已关闭 —— 本软件不会自动再弹一个。 | **浏览器已关闭（不会自动重开）** |

⚠️ **只改 Windows 线那一份**:macOS 的「Safari 复制修复」那条文案**一个字不动**
(mac 线由另一台机器负责)。
