# ADR-0007:参考字形库用 GBK 全集(gzip 分发)

- 状态:已定
- 日期:2026-10-21
- 相关:ADR-0006(按出现位置查表)

## 背景

还原的原理是"把密文字体的字形,拿去和参考字形库做最近邻匹配"。
参考库覆盖哪些字,就决定了**哪些明文字能被认出来**。

原方案:Noto Sans SC 48×48,**只含 GB2312**(7949 字,9.4MB)。

## 出问题的地方

参考库**缺**某个明文字时,最近邻会给出"形近但不是它"的字,
而且**分数与 margin 都能过闸门** → 直接**写出错字**。

实测(`tools/lab/probe-missing-char.cjs`,GB2312 库):

| 明文字 | 会被认成 | 相似度 | margin | 闸门 |
| --- | --- | --- | --- | --- |
| 燚 | **焱** | 0.812 | 0.074 | 全过 → 写错字 ✗ |
| 垚 | **寺** | 0.841 | 0.020 | 全过 → 写错字 ✗ |
| 鿕 | **鲋** | 0.837 | 0.011 | 全过 → 写错字 ✗ |
| 㶿 | **饽** | 0.895 | 0.029 | 全过 → 写错字 ✗ |

(燚/垚 这类字在人名里很常见,考试题面里出现并不罕见。)

**能不能靠提高阈值挡住?不能。** 真实字体的逐字分数最低只有 **0.8881**
(站点把字形重绘过,与参考字形不是逐位相同),
而错配案例的分数是 0.81~0.90 —— **区间重叠,阈值分不开"真匹配"与"缺字错配"**。

## 决定

参考库换成 **GBK 全集**(21526 字),gzip 随包分发(9.7MB)。

```
GB2312 库(7949 字)   9.4MB → gzip 2.2MB   ← 旧
GBK 全集(21526 字)  24.4MB → gzip 9.7MB   ← 现
```

换成全集后:真答案在库里 → 最近邻自然就是它;
仍然认不出来的(罕见字形)被闸门挡住 → **宁可留密文,不写错字**。
实测同一组生僻字在 GBK 库下:**零错字**(燚/垚/犇/靐/飝 正常识别,其余被闸门挡住)。

配套:加一道**零风险预筛** —— 自身距离不够(没被重映射)的码位直接跳过最近邻。
这与原判定**完全等价**(拟合率本来就要求自身距离达标),只是省掉全库检索,
普通 webfont 几乎全被跳过,不会因为库变大而拖慢。

## 代价

- 安装包 +7.5MB(DMG 约 136MB → 143MB)
- 单份字体的匹配变慢(132 码位:49ms → 593ms;真实站点 27 码位约 100ms)
  —— 靠预筛 + 字体内容哈希缓存抵消(同一份字体只算一次)
- 内存:解压后约 25MB

## 验证

- 真实站点字体(27 码位):**27/27 全对**(从/水/栽/回/利/土/凝/的/滴/区/注/泵/外/罐/学/会/公/室/业/精/新/员/需/极/盘)
- 仓库混淆字体 A/B(各 132 码位):**132/132 全对**,0 认错
- 生僻字探针:GB2312 库 4 例会写错字 → GBK 库 **0 例**
- 功能自测 7/7、核心单测 18/18、产物自检全绿
