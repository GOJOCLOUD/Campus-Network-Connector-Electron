# ADR-0008:形近字靠"常用字先验"分辨,并修掉一个让先验从未生效的 bug

- 状态:已定
- 日期:2026-10-21
- 相关:ADR-0007(参考库用 GBK 全集)

## 背景

真实测验页(大学生与创业(三))出现一个还原不出来的码位:`坉` → 应为「略」(战略管理能力)。

实测数据(站点字体 vs 参考库):

| 候选 | 分数 | margin |
| --- | --- | --- |
| **略**(田各) | 0.8496 | — |
| 挌(扌各) | 0.8472 | 0.0024 → 被闸门挡住 |

## 查清的过程(每一步都实测)

| 假设 | 验证 | 结论 |
| --- | --- | --- |
| 参考库里没有「略」 | 查 GBK 库 | ❌ 有 |
| 是 4bit 量化导致的 | 全精度重算 | ❌ 全精度 0.1288 vs 4bit 0.1276,几乎一样 |
| 是分辨率不够 | 48/64/96 三档重算 | ❌ margin 0.0156 / 0.0137 / 0.0151,基本不变 |
| 是粗筛把正确答案筛掉了 | 查正确答案的粗筛排名 | ❌ 排第 1、2 名,根本没被筛 |
| 是 margin 闸门太严 | 读引擎的实际判定 | ✅ **命中** |

## 根因

**两个独立的问题叠在一起**:

1. **「常用字优先」这个判定从来没生效过**:
   `COMMON_SET` 存的是**字符串**(`'格'`),而候选的 `codepoint` 是**数字**(`0x683C`)
   → `COMMON_SET.has(codepoint)` **永远 false** → 从写下来那天起,这个先验就是空转的。
   (代码里注释写着"常用字优先打破平局",实际一次都没生效过。)

2. **margin 闸门把"生僻字"也当成了同样说得通的竞争者**:
   格(木各) / 挌(扌各) / 恪(忄各) / 烙(火各) 只差左边一小块,
   48×48 的像素距离几乎一样(0.8496 vs 0.8472)。
   像素分不出,但**字频分得出**:挌/袼/恪 是生僻字,格是常用字。

## 决定

**给常用字一个先验加分,并用加分后的分数算 margin**:

```js
adjusted(c) = c.score + (COMMON_SET.has(c.codepoint) ? 0.02 : 0)
```

- 常用字 vs 生僻字 → 分得开 → 允许替换
  (实测「圻」:格 0.8496 vs 挌 0.8472 → 加分后 margin 0.0224 → 还原成「格」✓)
- 两个都是常用字(己/已/巳、略/赂)→ 加分抵消 → margin 仍小 → **不改**
- 两个都是生僻字 → 加分抵消 → **不改**

同时把 `COMMON_SET` 改成存**码位数字**,让这个先验真正生效。

## 影响

- 真实测验页(大学生与创业(三)):33 个密文码位,**32 个还原**,
  唯一没还原的是「坉」(见下)
- 仓库夹具两套字体:132/132 全对,无回归
- 通用性 7 个用例全过

## 剩下的边界:像素里没有答案的,只能靠语义

「坉」→ 该是「略」,但站点重绘后的「略」像素**离「赂」更近**
(赂 0.1007 vs 略 0.1162),**任何像素度量都选不对**。
而略/赂都是常用字 → 先验也分不出 → 系统**保守不改**,剪贴板里留「坉」。

- 这类情况**只能靠语境**("战X管理能力" → 战略)或字频细粒度区分,
  也就是设计文档里提过的"大模型做上下文消歧"——本版未做。
- 行为是安全的:**宁可留密文码位,也不写错字**。

## 验证

- `tools/lab/cipher-probe.cjs 19` → 密文码位 33 / 已还原 32 / 没能还原 1(坉)
- `tools/lab/diag-matcher.cjs` → 匹配器确实把「格」「略」排第一(是闸门挡的,不是没找到)
- `tools/lab/diag-weighted-distance.cjs` → 加权距离能放大 margin(0.0156 → 41.5),
  但**放大后胜出的仍是错的那个** → 证明这不是度量问题,是像素里没有答案
- `tools/lab/diag-blur-variants.cjs` → 三种口径对比,确认模糊与否不是关键
