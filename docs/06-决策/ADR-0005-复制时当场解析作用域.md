# ADR-0005:作用域在复制时当场解析,而不是依赖采集缓存

- 状态:已定
- 日期:2026-10-21
- 相关:ADR-0002(映射按字体建)

## 背景

映射表(码位 → 可见字)已经按**字体**整份下发,任意选区都覆盖得到(ADR-0002)。
但页面守卫查表时还要先知道"**这个字符属于哪个字体作用域**"。旧实现把这个信息
存在 `charScopes` 里,而 `charScopes` 是**采集缓存** —— 由 `selectionchange` 和
App 的轮询更新,**比复制慢一拍**。

## 出问题的地方

真实故障:学习通测验页复制,剪贴板里

```
【单选题】固定导轨的安装扣最先在()的安装上使用。   ← 修好了
【判断题】一旦有人提出无抲宣告请求,专利局抸者法抶就必曳抷理。  ← 抲/抸/抶/曳/抷 还是密文
```

诊断结论:

- 页面上 `font-cxsecret` **只有一个** `@font-face`,作用域只有一个,映射表 19 条**齐全**
  (抲→效、抸→或、抶→院、曳→须、抷→审 都在表里)
- 没修好的 5 个字是**判断题独有的**(单选题里没出现过),
  而它们没被替换的原因不是"表里没有",而是**查表落空**:
  `state.charScopes[那个字]` 当时还是空的 → 拿不到作用域 → 只能原样输出

一句话:**映射表是全的,但"这个字属于哪个字体"这份缓存没赶上**。
早先选过的字在缓存里 → 修好了;刚选到的字不在 → 没修。

## 候选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A 复制时按当前选区从 DOM 现算作用域 | 零延迟、零缓存,永远与选区一致 | 每次复制要遍历一次选区文本节点 | **采纳** |
| B 加快采集频率 | 改动小 | 仍是竞态:用户永远可能比采集快 | 否决 |
| C 复制时在所有作用域里全局搜这个字 | 简单 | 会把正常字误替换:明文字"户"恰好是密文映射表的键 | 否决 |

## 决定

**复制时当场解析作用域**(守卫 v6):

1. copy 事件里按**当前选区**从 DOM 现算"字符 → 作用域 key",
   作用域 key 公式与采集路径完全一致(否则对不上 App 下发的表)
2. 解析不出来的字符才回退到采集缓存
3. 解析结果**回写**采集缓存,让缓存也跟着当前选区走

作用域 key 里含**字体内容指纹**,所以"站点换字体"仍然会换作用域、重新建映射 ——
这一点没有因为改成当场解析而放松。

## 代价

- 每次复制多一次 DOM 遍历(实测选区 119 字时 < 1ms)
- 守卫多了 `resolveLiveScopes`,`GUARD_VERSION` 5 → 6(旧守卫会被自动替换)
