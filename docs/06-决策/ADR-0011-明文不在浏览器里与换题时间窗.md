# ADR-0011:明文不在浏览器里;换题后的"映射就绪窗口"要压到最小

- 状态:已定
- 日期:2026-10-21
- 相关:ADR-0009(换题自动适配)、ADR-0010(根因:站点把字画细了)

## 背景

用户提出两个关键质疑:

1. **"既然它能显示的正确,那一定有一个地方是存在正确的"** —— 明文会不会就在页面里?
2. **"每次换题就失败"** —— 换题后到底发生了什么?

## 一、明文不在浏览器里(实测)

穷举搜索(全部 frame):DOM 文本、所有属性、`<script>` 内容、`<input>/<textarea>` 的值、
注释节点、`window` 上所有可 JSON 化的全局变量。

> 结论:**整页没有明文**。而且"课程标题"这种公共文本会命中 → 必须用**题干正文**的短语做探针,
> 否则是假阳性。

再取同源接口响应(题目 frame 自己的 URL,带 cookie):

```
GET https://mooc1.chaoxing.com/mooc-ans/work/doHomeWorkNew?...&enc=...
→ 200, 113301 字节
→ 里面是：role="radio" aria-label='A 企嵻嵽嵼选择'      ← **服务端发来的就是密文**
→ 同一份响应里别的题目却是明文（"数值计算库""科学计算库"）← 只有考试题被混淆
```

**=> 混淆是服务端做的,明文从一开始就没到过浏览器。**

### 站点到底改了什么?(2026-10-21 12:59 补测)

查字体 cmap 里到底装了哪些码位(`tools/lab/diag-what-changed.cjs`):

| 字体 | cmap 码位总数 | 密文码位 | **明文字** | 其它 |
| --- | --- | --- | --- | --- |
| 真实 · 大学生与创业(二) | 25 | 25 | **0** | 0 |
| 真实 · TRIZ理论(十一) | 44 | 44 | **0** | 0 |

**=> 站点做的是两件事:**

```
原始题面:「在创业必备的素质中,()能够体现企业的发展方向。」

① 改 DOM 文本:把「能/够/体/现/企/业…」换成密文码位
② 改字库:自制 @font-face,cmap 里**只有那些密文码位**,
   每个码位上放的是**明文字的字形**(更细的字重 350)

显示 → 浏览器拿密文码位问字体 → 字体画的是明文字的形状 → 看起来完全正常 ✔
复制 → 浏览器复制 DOM 里的**码位** → 全是生僻字 ✘
```

**=> 显示本身没被"改",显示只是字库生效的结果;真正被改的是字库(字形搬家)+ DOM 文本(换码位)✓**

### 码位每次都重新随机发(实测)

| 明文字 | 题 A 的密文码位 | 题 B 的密文码位 |
| --- | --- | --- |
| 的 | 厙 (U+5399) | 摳 (U+6473) |

**=> 同一个字,两套题用了完全不同的码位 ✓ → 标签是每次重新随机发的 ✓**
**=> 任何"记住映射/查固定表"的做法都不可能通用 ✓ —— 只有认形状这一条路成立 ✓**

### 站点为什么"不会去改图形"(工程约束,不是技术限制)

技术上做得到(他完全可以画一套歪七扭八的字形),但**不划算**:
题库是以明文存的,要把每道题的每个字都换成怪图形 = **整个题库重做** ✗
所以他只能做"渲染时的通用变换":**换码位、不换字形** ✓

**=> 这条约束是"我们必然还原得出来"的结构性保证:**
只要站点还在用真字形冒充,我们就一定认得出来 ✓
(哪天他换整套题库格式,那是另一件事 ✓)

### 这正是"反推字形"这条路能成立的根本依据

明文字**根本不在站点的字体里**(浏览器手里一个都没有)→

- 不可能"读出"明文 ✗(只能反推)
- **反推必然能成功**:字形本身就是明文字的形状(只差粗细,二值形状距离 0.027 ≈ 逐格相同)✓

**=> 只要站点还是"把明文字的形状搬到别的码位"这套玩法(它必须这样,否则题面没法看),
   拿参考库反查就一定能认出来 ✓ —— 换题、换科目、换码位、换字重都不影响 ✓**

### 那"能显示正确"的东西在哪?

只剩两处:**字体里的字形**、**屏幕上的像素**。

- **像素路径(canvas 渲染回传)拿不到新信息**:它渲染的还是同一个字形,
  只是换了栅格化器 → 形状信息完全相同。当年报废它是因为**度量旧**,
  不是因为"读像素"这个方向错。
  它真正的优势只在**字体文件读不到时**(跨源 @font-face)才成立 —— 本站不是这种情况。

**=> 结论:反推字形是唯一可行路径;要做的是把度量做对(ADR-0010),而不是换路径。**

## 二、"换题就失败"的真正机制(复现)

用夹具(同标签内换字体)复现:

```
换题 → 立刻复制 → 剪贴板 = "天地玄黄宇宙洪荒日月盈昃…"   ← 原始密文!
第 1 轮后复制 → ✔ 正确（换题后 1956ms）
```

**=> 不是识别不准,是"新字体的映射还没建好"这一段时间里复制,拿到的是原始密文。**
用户看到的"乱七八糟"就是这个。

两个成因:

| # | 成因 | 修法 |
| --- | --- | --- |
| 1 | **预热与选区用了不同阈值**(0.88 / 0.8)→ 预热下发的表少几条 → 换题后第一张表就是"缺字"的 | 两边统一用 `minScore`;图标字体本来就有字体级拟合率闸门挡着 |
| 2 | 主轮次一圈要轮询多个标签(每个标签一次 Apple Event,实测一圈 ~1.4 秒)→ 新字体最��� 2 秒才被处理 | 给"带混淆字体的标签"单开一个**快轮询**(~200ms 一轮,独立于主轮次) |

修完:换题后映射就绪时间从 **~2.0s 降到 ~0.5s**。

## 三、顺带补上的验证盲区

之前的验收一直是 `selectNodeContents`（**单节点整选**）,而真人**鼠标拖选**出来的是
**跨多个文本节点、两端还不取整节点**的 Range —— 喂给守卫的 `selection.toString()` 完全不同。

实测(真实页面,跨 18 个节点、147 字):

```
剪贴板 148 字：「向。/A/企业性质/B/企业产品/C/企业战略/…」  ← 全部还原 ✔
```

**=> 这条路径本身是好的**,但之前**没有测试覆盖** → 已补进 `switch-quiz.cjs` 阶段4
(用**当前题库的映射表**算期望值,与题目内容无关)。
