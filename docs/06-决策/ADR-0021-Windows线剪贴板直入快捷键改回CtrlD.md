# ADR-0021:Windows 线「读剪贴板并键入」的快捷键改回 **⌃D**(⌃⇧D 降为容错别名)

- 状态:**已定**(用户 2026-10-27 原话:「把快捷键都搞成 Ctrl+D」)
- 日期:2026-10-27
- 相关:ADR-0017(Windows 线抢 ⌃⇧D —— **本文取代它的「键位」部分**)、
  ADR-0013(Windows 线与 macOS 线行为对齐)、ADR-0020(Windows 线自起浏览器 + CDP 注入守卫)
- 性质:定下 Windows 线**全局键的键位**与**触发方式**。
- 谱系:Tauri 侧是**同一条决策**的 ADR-0031,两边行为一致。

---

## 一、为什么又改回去

| 时间 | 键位 | 用户原话 |
| --- | --- | --- |
| 2026-10-24(初版) | ⌃D | 「干脆直接把系统的抢了,我的软件优先级最高……Ctrl 加 D 我发现在普通桌面它是退出软件的功能,那在使用这个的时候没必要退出吧,所以就给他压制住」 |
| 2026-10-25(第二次改口径) | ⌃⇧D | 「你不要用 ctrl+D 了,直接 ctrl+shift+D 吧」 |
| **2026-10-27(现行)** | **⌃D** | 「**把快捷键都搞成 Ctrl+D**」 |

10-25 换键的理由是「**⌃D 冲突太重**」—— 在普通 Windows 软件里 Ctrl+D 常常是
「退出软件」那一族动作(菜单加速键),抢它容易和别人打架,而 ⌃⇧D 几乎没人用
⇒ 抢到的概率高得多。

**这次改回去,是因为用户要的就是这个键**,而且这个产品**就该按市面惯例来**:

- 主流软件对「本软件自己的快捷键」就是**按用户点的那个键**来,不做二次发明;
- 本产品里「从剪贴板读入并键入」的**按钮已经撤掉**(ADR-0017 决策四)
  ⇒ 入口只剩全局键 ⇒ **键位就是它的全部可发现性**,不能藏;
- mac 线(Tauri 侧)的窗口内判定本来就是「**只认 Control**」
  ⇒ ⌃D 与那条判定口径一致。

## 二、「怎么操作」按市面惯例来:宽容 + 如实反馈

市面上做全局热键的工具,公认做法是这三条,本产品照做:

1. **匹配要宽容** —— 多带一个修饰键也算数。
   mac 线是自己监听按键、只看「**有没有** Control」(10-23 用户要求:「只要按住 Ctrl
   再点一下字母」);而 Windows 的系统全局热键(`RegisterHotKey`)是**精确匹配**
   ⇒ 手上多带一个 Shift 就对不上、按键**不被吃掉**、那个 D 漏进前台应用
   (10-23 用户抱怨过的「多打出一个 D」),动作也不执行(看起来像失灵)。
   ⇒ **Windows 侧额外注册 `Ctrl+Shift+D` 作容错别名**,主键是 `Ctrl+D`。
   (别名本来就是 10-25 之后的主键 ⇒ **不新增占用**。)
2. **latch** —— 触发一次之后必须**松开 Control** 才重新武装(按住 Ctrl 连按不会连着触发)。
   规则不变。
3. **抢没抢到要如实说** —— 界面那行琥珀色提示照旧,只是文案改成 ⌃D,
   并把「别的软件里的 Ctrl+D 会收不到」这句实话写进去。

## 三、代价(必须说清楚)

⌃D 在别的软件里是常用键:

| 软件 | Ctrl+D 是干什么 |
| --- | --- |
| Edge / Chrome | 收藏夹 |
| VS Code | 选中下一处相同文本 |
| Excel | 向下填充 |
| 不少国产软件 | 删除 / 退出那一族 |

⇒ **本软件开着的时候,别的软件里按 Ctrl+D 它们收不到。**
这是「抢全局键」这件事的固有代价,不是 bug。
界面提示与本文档都写明,不让用户以为「按了没反应」是系统坏了。

## 五、mac 线待办(那边机器负责)

mac 线(Electron 仓 `mac` 分支 / Tauri 仓 `mac` 分支)的全局键**现在仍是 ⌃⇧D**
⇒ **两边的键位暂时不一致**,与 ADR-0013「行为对齐」有出入。

⇒ **待办**:mac 线也把主键换成 ⌃D(⌃⇧D 同样降为容错别名),两边重新一致。
本仓只读不动 mac 分支,故不在此仓实施。

- **Rust 单测**(Tauri):`光Control的D就触发`。
- **真机**(待做):在别的软件里按 ⌃D ⇒ 本软件把剪贴板内容逐字键入,
