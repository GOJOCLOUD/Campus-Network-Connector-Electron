# ADR-0009:换题必须自动适配 —— 预热阈值对齐 + 二值距离(比形状不比粗细)

- 状态:已定
- 日期:2026-10-21
- 相关:ADR-0002(映射按字体建)、ADR-0005(复制时当场解析作用域)、ADR-0008(常用字先验)

## 背景

用户每换一套题,站点就换一套加密字体(码位全不同)。系统必须做到:
1. 自动发现新字体 → 自动建映射 → 自动下发,**不需要任何人工干预**
2. 旧题目的映射**不能**用到新题目上(否则会把字还原成上一套的答案 → 写出错字)

这两条**设计上**是成立的(作用域 key 含字体内容指纹;映射按字体建;守卫在 frame 重建后自愈),
但**没有一条专门的回归测试**,于是"换题就失败"一直靠人肉发现。

## 换题回归测试(新增)

`src/features/safari-repair/test/switch-quiz.cjs`:同一个标签里来回换字体(A↔B↔A↔B)。

夹具里两套字体**码位相同、画成不同的字**(A: 天→人 地→工;B: 天→工 地→智),
所以旧映射一旦泄漏,测出来的答案会**明确错掉**(人 vs 工),不会有歧义。

**这条测试第一次跑就抓出两个真 bug。**

## Bug 1:预热与选区用了**不同的阈值** → 换题后第一批复制必然缺字

| 路径 | 阈值 | 映射条数 |
| --- | --- | --- |
| 预热(扫全页自定义字体) | `minPrefetchScore` 0.88 | **131** |
| 选区采集 | `minScore` 0.8 | **132** |

差的正是「调→需」(它的分数落在 0.8~0.88 之间)。

**时序**:换题 → 页面重建 → 预热把 131 条的表下发 → **用户选中就立刻复制** →
此时页面上只有这张表 → 「调」查不到 → 复制出来一半是密文。
等选区的采集跑完再复制才会补上 —— 而用户往往就是"选中立刻复制"。

**修法**:预热与选区**用同一个阈值**(`minScore`)。
预热原本更严是为了挡图标字体,但那件事**字体级拟合率闸门(≥0.7)已经在做**
(实测 icomoon 只有 3% → 直接判为普通字体、压根不建映射),
逐字更严的阈值是多余的。

## Bug 2:站点的重绘**笔画更细** → 灰度距离偏向"笔画少"的字

真实测验页(企业/创业素质)的「战略」还原不出来,码位是「嶀」。

排查(每一步都实测):

| 假设 | 验证 | 结论 |
| --- | --- | --- |
| 参考库里没有「略」 | 查 GBK 库 | ❌ 有 |
| 分辨率不够 | 48/64/96 三档 | ❌ margin 几乎不变 |
| 粗筛筛掉了正确答案 | 查粗筛排名 | ❌ 排第 1、2 名 |
| margin 闸门太严 | 读引擎判定 | ✅ 命中 |
| 加权距离能救 | 按格子区分度加权 | ❌ 放大 26 倍,胜出的仍是错的那个 |

**把字形画成 ASCII 才看清真相**:站点画的是「田+各」= **略**(左边是框里加十字),
参考的「赂」左边是「贝」(框里两条腿)。**站点画的是对的,是度量错了。**

原因:站点重绘的笔画比参考**细**,于是"笔画少一半"的「赂」在灰度 L1 下反而更近:

| 口径 | 略 | 赂 | 结果 |
| --- | --- | --- | --- |
| 灰度 L1(原口径) | 0.1493 | 0.1512 | 略赢,但 margin 只有 0.0019 → 被闸门挡 |
| **二值差异(比形状)** | **0.0920** | 0.1042 | 略赢,margin **0.0122** → 过闸门 ✓ |

**修法**:精筛阶段同时算两种距离 ——
- `score`:灰度 L1(沿用原口径,分数闸门 0.8/0.88 不动)
- `distance`:**二值差异**(nibble ≥ 8 视为有笔画)→ 排序与 margin 用它

即"**比形状,不比粗细**"。这是站点的通用做法(所有加密字体的笔画都比参考细),
**调阈值解决不了,必须在度量上解决**。

## 影响

| 项 | 之前 | 之后 |
| --- | --- | --- |
| 换题回归(6 个场景) | ✖ 1 个字没还原 | ✔ 全过 |
| 真实题(企业/创业素质) | 26/27 | **27/27**,「企业战略」✓ |
| 真实题(大学生与创业三) | 32/33 | 33/33 ✓ |
| 仓库夹具字体 A/B | 132/132 | 132/132(无回归) |
| 图标字体(icomoon/VideoJS) | 判为普通字体 | 仍然判为普通字体 ✓ |
