# 新功能开发指南

## 目录约定

每个功能一个自包含目录:

```
src/features/<功能名>/
├── index.js      模块入口:init / registerIpc / dispose
├── (其它实现文件)
├── paths.js      可选:统一算项目根与 vendor 的路径
├── README.md     这个功能怎么用、怎么测
└── test/          可选:该功能的自测脚本(不进安装包)
```

## 功能模块契约

```js
module.exports = {
  id: 'my-feature',          // 唯一标识,也是配置命名空间
  title: '我的功能',          // 界面显示名
  init(ctx) { /* 返回实例 */ },
  registerIpc(ipcMain, { settings }) {},
  dispose() {},
};
```

`ctx` 提供:

| 字段 | 说明 |
| --- | --- |
| `app` | Electron app 对象 |
| `ipcMain` | 用于注册 IPC |
| `log` | 日志函数 |
| `settings` | **本功能专属**的配置命名空间:`get(key, fallback)` / `set(key, value)` |

配置最终落在 `settings.json`:

```json
{ "features": { "my-feature": { "enabled": true } } }
```

## 加一个功能的完整步骤

1. `mkdir src/features/my-feature`,写 `index.js`
2. `src/features/index.js` 的 `FEATURES` 里加一行:`{ id: 'my-feature', title: '我的功能', module: './my-feature' }`
3. 在你的 `registerIpc` 里注册开关 IPC:`ipcMain.handle('<prefix>:setEnabled', ...)`
   （`<prefix>` 由 id 推导:`my-feature` → `myFeature`）
4. **前端不用改**:界面第 4 页的功能开关区由 `features:list` 清单驱动,
   `featureList.map(...)` 自动渲染,点开关时按 `f.prefix` 调 `ipcRenderer.send(prefix + ':setEnabled', v)`。
5. 写 `src/features/my-feature/test/xxx.cjs` 自测脚本
6. 在 `package.json` 的 `files` 里确认**没有**误把测试/文档打进包
   （`!src/features/**/test/**/*` 已经排除,新功能目录自动适用）
7. 跑 `node tools/verify/verify-package.cjs` 确认产物干净

## 本地调试

```bash
# 起 App(开发模式)
npm run electron

# 跑全部功能的自测
npm test

# 校验打包产物
node tools/verify/verify-package.cjs
```

> Safari 的自测脚本会**真实操作 Safari 标签页**,必须串行跑(`--test-concurrency=1`),
> 否则两个脚本互相抢标签索引,会产生假失败。

## 注意事项

- 路径一律用 `paths.js` 算,不要在业务代码里写 `path.join(__dirname, '..', '..')`
- 原生模块(.node)必须能被 electron-builder 解包(`asarUnpack`),否则装上就静默失效(见 ADR-0003)
- 新增第三方运行时依赖放 `vendor/`,并加进 `package.json` 的 `files`
- 功能自己的设置**不要**往 main.js 加全局变量,放进 `ctx.settings` 的命名空间
