# 实现地图

## packages/core(算法核心,浏览器无关)

| 模块 | 职责 |
| --- | --- |
| `glyph-matching/raster.ts` | 轮廓 → 覆盖度位图(同一套栅格化器,参考库与查询共用) |
| `glyph-matching/db.ts` | 参考字形库:建库、序列化、最近邻检索、自身距离 |
| `glyph-matching/policy.ts` | 判定策略:什么算"混淆字体"、什么才允许替换 |
| `copy/selection.ts` `copy/repair.ts` | 选区文本 → 修复后文本 |
| `mapping-cache/` | 映射缓存 |

## packages/browser-adapters(浏览器适配)

| 模块 | 职责 |
| --- | --- |
| `packages/browser-adapters/shared/src/page-guard.ts` | 注入网页的守卫:采集作用域、上报字体、copy 时**当场按选区解析作用域**再改写(见 ADR-0005) |
| `packages/browser-adapters/shared/src/frame-bridge.ts` | 递归注入所有同源 frame、汇总上报、自愈 |
| `packages/browser-adapters/shared/src/common-charset.ts` | 常用字集(3901 字) |

## src/features/(Electron 应用层,按功能自包含)

| 路径 | 职责 |
| --- | --- |
| `src/features/index.js` | **功能注册表**:新增功能的唯一入口(FEATURES 数组) |
| `src/features/safari-repair/index.js` | 该功能的入口:init / registerIpc / dispose |
| `src/features/safari-repair/coordinator.js` | 调度:轮询标签、注入守卫、下发映射、**快轮询**(新内容出现后 200ms 一查) |
| `src/features/safari-repair/bridge.js` | 走 Apple Events 与 Safari 通信(注入 JS、读状态) |
| `src/features/safari-repair/engine.js` | 匹配引擎:字体 → 码位→明文映射表(口径见下) |
| `src/features/safari-repair/fast-matcher.js` | 精筛:同时算灰度分与二值距离,按 distance 排序 |
| `src/features/safari-repair/paths.js` | 统一算项目根与 vendor 路径(别在业务代码里拼相对路径) |
| `src/features/safari-repair/test/` | 该功能的自测脚本(不进安装包) |

> 功能之间**不互相引用**:加新功能 = 建目录 + 在 `src/features/index.js` 加一行。
> 详见 [新功能开发指南.md](新功能开发指南.md)。

## 关键数据流

```
页面守卫 ──(字体文件 + 字符集合)──▶ App 侧引擎
                                      │  opentype.js 解析 → 栅格化 → 最近邻匹配
                                      ▼
页面守卫 ◀──(码位→字符 映射表)──── App 侧引擎
   │
   └─ copy 事件:查表 → setData('text/plain', 修复后) + preventDefault
```

## 三条口径不能各写各的

| 口径 | 在哪 | 规则 |
| --- | --- | --- |
| 栅格化 | `packages/core/src/glyph-matching/raster.ts` | 参考库与查询侧必须用**同一个** `rasterizeContours`、同一尺寸、同一量化方式 |
| 参考库 | `vendor/glyph-db-48.crdb.gz` | **只有一份真身**(随包分发)。`tools/reference-fonts/*.crdb` 是同内容的未压缩构建产物,脚本不要直接读它 —— 两份会漂移,诊断结论就跟线上对不上了。统一走 `engine.loadReferenceDb()` |
| 替换判定 | `packages/core/src/glyph-matching/policy.ts` + `engine.js` 的 `DEFAULTS` | 分数闸门用灰度 L1,排序与 margin 用**二值距离**(比形状不比浓淡) |

## 栅格化口径必须一致

参考库与查询侧用**同一个** `rasterizeContours`、同一尺寸、同一量化方式。
两边不一致时距离会整体抬高,近邻就会判错(实测:页面 canvas 渲染 vs 参考库,
「专」被判成「令」)。详见 [02-设计/字体混淆还原-字体文件解析方案.md](../02-设计/字体混淆还原-字体文件解析方案.md)。
