# 算法与实验侧说明

> 本仓是**一个仓库两件事**:产品侧是 Electron 桌面 App(`src/`、`main.js`),
> 算法侧是字形还原的核心与浏览器适配(`packages/`、`apps/`、`tests/`、`tools/`)。
> 2026-10-21 起,原先独立的「浏览器修复」算法仓已**整体并入本仓**。

## 算法侧在做什么

在网页用**字体混淆**(把要显示的字画在别的码位上)或**篡改 copy 事件**时,
把复制结果还原成用户**看到**的文字。

当前生效的路线:**解析字体文件 → 逐码位栅格化 → 与参考字形库最近邻匹配**。

> 早期路线是「页面 canvas 渲染字形再回传比对」,已废弃:
> 页面与参考库的栅格化器不同,相似度只有 0.87~0.97,会把「专」判成「令」。
> 详见 [02-设计/字体混淆还原-字体文件解析方案.md](../02-设计/字体混淆还原-字体文件解析方案.md)。

## 目录

```
packages/core/                 算法核心(字形匹配、判定策略、参考库、映射缓存)—— TypeScript
packages/browser-adapters/     浏览器适配(页面守卫 page-guard、frame 桥、渲染)
apps/chromium-extension/       Chromium 扩展(MV3,可直接分发)
apps/safari-extension/         Safari Web Extension 源码(需付费团队签名,当前不可分发)
tests/                         跨浏览器端到端测试 + 测试页夹具(A~H)
tools/                         构建与实验脚本(见 tools/README.md)
vendor/                        构建产物(参考库、注入脚本)—— **进安装包**
```

## 构建与测试

```bash
npm install

# 注入产物(改了 packages/browser-adapters 之后必须重建,否则装出去的还是旧守卫)
npm run build:vendor            # → vendor/page-guard.js 等

# 参考字形库(要换参考字体/栅格尺寸时才需要重建)
npm run build:reference-db      # → tools/reference-fonts/glyph-db-48-gbk.crdb

# Chromium 扩展 / Safari 扩展(辅助形态,主交付是 Electron App)
npm run build:core              # → dist-core/chromium、dist-core/safari

# 测试
npm run test:core               # 算法核心单元测试(浏览器无关)
npm run test:e2e                # Chromium 端到端(会开真实浏览器窗口)
npm test                        # 产品侧功能自测(会真实操作 Safari,必须串行)
```

> `dist-core/` 与 `release-core/` 是算法侧的构建输出,
> 和产品侧的 `dist/`(vite 前端)、`release/`(electron-builder)刻意分开,避免互相清空。
