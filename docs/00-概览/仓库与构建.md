# 仓库与构建

## 这是什么

算法侧(copy-repair):把"网页里被字体混淆的文字"还原成用户看到的文字,并顺带处理
copy 事件篡改(网页在 copy 时改写内容)。**2026-10-21 起已并入 `Campus-Network-Connector`**,不再是独立仓库。两条实现路线:

| 路线 | 形态 | 状态 |
| --- | --- | --- |
| Chromium 扩展 | `apps/chromium-extension/`(MV3) | ✅ 可直接分发,自带参考库 |
| Safari | 原生 App 注入(本仓 `src/features/safari-repair/`) | ✅ 走 Apple Events,不需要 Safari 扩展 |
| Safari 扩展 | `apps/safari-extension/` | ❌ free 个人团队签不出扩展点描述文件 |
| Safari 热键工具 | `tools/build-safari-tool.mjs` | ⚠️ 只能修复制劫持,修不了字形混淆 |

## 构建

```bash
npm install

node tools/build.mjs chromium     # → dist-core/chromium/   (可直接加载的扩展)
node tools/build-vendor.mjs       # → vendor/         (参考库 + 注入脚本 + 共享核心)
npm run build:reference-db         # 重建 48×48 GBK 全集参考库 → tools/reference-fonts/glyph-db-48-gbk.crdb
node tools/build-page-guard.mjs   # → dist-core/page-guard/
```

## 测试

```bash
npm run test:core                              # 单元
npm run test:e2e                               # Chromium 端到端(会开真实 Chrome 窗口)
npm test                                       # 产品侧功能自测(会真实操作 Safari,必须串行)
```

## 产物去哪

- `dist-core/chromium/` → 打包成 zip 分发
- `vendor/` → **进安装包**(Electron App 注入到网页的就是这里的 `page-guard.js`)
