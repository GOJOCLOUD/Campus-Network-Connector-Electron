# 三、下午这段:用户 18:01 提的三件事

## 3.1 「一打开就反反复复拉起浏览器、每次都失败、根本没有窗口」

**先说结论:不是「浏览器起不来」,是「用户关掉窗口之后,软件又给弹一个」。**

### 取证(真机,不是猜)

| 步骤 | 观察到的 |
| --- | --- |
| 带时间戳观察 App | 连续三次「启动 Edge(端口 61655 → 58658 → 59831)」⇒ **每次都新起了一个** |
| **对照实验**:用**完全相同**的参数手动起 Edge | **6/6 全部 1 秒内开好调试端口**、窗口正常 ⇒ 起浏览器本身没问题 |
| **关窗实验**:App 正常运行 ⇒ **关掉 Edge 窗口** | **约 20 秒后 App 又拉起一个新的**(带「还原页面」气泡、之前开的标签页全丢) |
| Edge 无崩溃报告、事件日志干净 | 是**干净退出**,不是崩溃 |

⇒ 六个坑,一起堵上(ADR-0024):

1. `ensure()` 没有互斥 ⇒ 并发调用各起一个;
2. 连「已经在跑的浏览器」白等 5 秒;
3. `findRunningPorts()` 用 `execFileSync` **卡死 Electron 主线程最多 15 秒**
   ⇒ 界面不刷新、CDP 事件不处理、⌃D 的钩子拿不到回调;
4. 起不来无限重试;
5. Edge 自己的 stdout/stderr 被 `stdio:'ignore'` **全丢了** ⇒ 出了事一个字都没有;
6. 分不清「用户关的」和「崩的」。

### 关键假设已实测

| 怎么关的 | 进程退出码 | 判定 |
| --- | --- | --- |
| CDP `Browser.close`(= 用户点叉) | **0** | 「用户关掉了窗口」⇒ **不自动再弹** |
| `Stop-Process -Force`(= 崩了/被强杀) | **4294967295** | 「异常退出」⇒ **仍然自动恢复** |

⇒ 两条路分得开。

### 现在是什么行为

- **你自己关掉那个 Edge 窗口** ⇒ 软件**不会**再自动弹一个;
  界面上出现「浏览器已关闭 —— 本软件不会自动再弹一个」+ 一个 **「重新打开浏览器」** 按钮。
- **浏览器崩了 / 被强杀** ⇒ 仍然**自动恢复**。
- **连着 3 次起不来** ⇒ 软件**停下来**,并把原因写在界面上(不再无限重试)。

### 抓到并修掉的**两个** race

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 已经认出「用户关的」,却还是弹了一个 | 判定放在 tick 开头,而「进程退出」与 tick 之间有时间差 | 判定挪到**真正起浏览器之前** |
| 2 | CI 门禁红:「没认出是用户关掉了窗口」 | `'exit'` 事件是 Node 事件循环**异步**派发的 ⇒ 进程已经死了、事件还没送到时,标志还是 false | 不看标志,**把退出码等出来**再决定(Electron 最多等 3 秒 / Rust 用 `try_wait()` 在判定前**再读一次**) |

## 七、怎么自己验一遍(用户视角)

1. 装上其中一个安装包(两个都行,功能一样,只是技术栈不同);
2. 启动软件 → 最后一页(键盘输入那一页)最上面 → 打开「浏览器复制修复」;
3. 软件会打开**它自己的** Edge 窗口 —— **在那个窗口里**扫码登录超星、
   进题、拖选题干、Ctrl+C ⇒ 复制出来就是**明文**;
4. 想知道自己在测哪个版本 ⇒ 看**左上角的小标签**、**托盘悬停**、**任务栏悬停提示**;
5. 「读剪贴板并键入」= **⌃D**(⌃⇧D 是容错别名)。
   软件开着的时候别的软件收不到 ⌃D(Edge 的收藏夹、VS Code 的选中下一处、Excel 的向下填充);
   软件**也**装了低级键盘钩子,所以微信那类用钩子抢键的软件压不过我们 ——
   但 Windows 是「**后装的钩子先被调用**」⇒ **把本软件放在那些软件之后启动**才稳赢。

## 8.1 三条各自的根因与修法

| 用户说的 | 真机抓到的根因 | 修法 |
| --- | --- | --- |
| 右上角「最小化 / 叉叉」**完全点不动** | **拖拽区把真实鼠标点击吃了**:`Stepper` 里「步骤圈 + 进度线」那一行带拖拽区标记,它的**矩形横跨整张卡片**、右上角正好压在窗口按钮上。拖拽区是**按矩形**算的,「不拖拽」只有在**这个元素是拖拽元素的子孙**时才会挖空;而按钮容器是那一行的**兄弟** ⇒ 挖不空 ⇒ 浏览器进程把真实鼠标按下当成了「拖窗口」⇒ **点击进不到渲染器** | 那一行**不再声明拖拽区**(根容器的矩形本来就覆盖整窗,那一行照样能拖窗口) |
| 那一栏说明**太长、乱七八糟** | `description`(21 字)+ `hint`(57 字)+「浏览器已关闭」那一行(20 字)叠在一起 | 界面上只留**必须当下知道的一句**;并加门禁卡长度上限 |
| 点开关就**不断拉起浏览器、页面超多** | ① `--restore-last-session`:每次启动都把上次会话的标签页全恢复出来(上次那堆里又装着上次恢复的)⇒ **滚雪球**(实测一次启动就恢复出 **21 个 `about:blank`**);② 标签页一多 ⇒ 浏览器起得慢 ⇒ 调试端口迟迟不开;③ **连不上 CDP 不计失败次数** ⇒「起不来上限 3 次」形同虚设 | ① 去掉 `--restore-last-session`(登录不受影响,cookie 在 profile 里);② 连接失败**也计次**;③ **已经有浏览器在跑就不再起新的**(同 profile 再起一个只是 Chromium 的「转发启动」,只会多开一个标签页) |

⚠️ **为什么这个问题之前一直看不出来**:CDP 伪造的点击会**绕过**浏览器进程的拖拽区判定 ⇒
脚本点一下永远是好的,**只有真人用鼠标点**才会暴露。
「不拖拽」的标记这些**本来就写对了**,光看源码看不出来。
