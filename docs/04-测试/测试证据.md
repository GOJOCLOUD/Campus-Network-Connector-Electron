## 4. 复制提交机制 —— ✅ 实测（决定性结论）

```bash
node tools/proto-clipboard-commit.mjs
```

```
1) Cmd+C 无改写          => "SENTINEL"              ← CDP 合成按键不触发 macOS 原生复制
2) Cmd+C + setData       => "SENTINEL"
3) Cmd+C + 异步写入      => "SENTINEL"
   setData + preventDefault => "MODIFIED-WITH-PD"     ✅ 只有这条会提交事件里的改写
```

结论：**Chromium 只有在 copy 事件被 `preventDefault()` 时才提交事件里的 clipboardData**。
扩展据此在"确实产出验证过的替换文本"时才调用 `preventDefault()`，
普通网页完全走浏览器原生路径。

| App 启动后 Safari 加载扩展 | ❌ **验证失败** | Safari 设置→扩展列表**为空**；`SFSafariExtensionManager.getStateOfSafariExtension` → `SFErrorDomain Code=1`；无扩展进程 |

**阻塞根因（已定位）**：Xcode 登录的是 **free 个人团队**（teamID `769LN7AY28`,
`isFreeProvisioningTeam=1`）。用该团队构建时编译与签名都成功，
但**签不出 Safari Web Extension 扩展点的描述文件**（appex 无 `embedded.provisionprofile`，
entitlements 缺 `application-identifier` / `com.apple.developer.team-identifier`），
Safari 的 ExtensionFoundation 因此不加载它——设置里的扩展列表为空。
→ **需要付费 Apple Developer Program 团队**（详见安装指南第 4 节）。

次要阻塞（自动化通道）：Safari 偏好在受 TCC 保护的沙箱容器内，
本机进程没有「完全磁盘访问权限」→ `defaults write com.apple.Safari` 被系统拒绝；
`osascript` 没有「辅助功能权限」→ 无法自动点开「允许未签名的扩展」与扩展开关；
`safaridriver --enable` 需要管理员密码。
因此这一步必须由用户手动完成（见 `../05-运维/安装指南-macOS-Safari.md` 第 2 节，5 步），
随后 `node tools/safari-check.mjs` 可立即产出与 Chromium 同等强度的证据。

```bash
node tools/build-page-guard.mjs
node tools/safari-guard-verify.mjs
```

```
✔ none                     无劫持（基线）
✔ win-capture-setdata      网页在 window 捕获阶段 setData（先注册）
✔ win-capture-prevent      网页在 window 捕获阶段 preventDefault
✔ doc-capture-setdata      网页在 document 捕获阶段 setData
✔ doc-bubble-setdata       网页在 document 冒泡阶段 setData
✔ doc-bubble-stopimmediate 网页 stopImmediatePropagation
✔ cached-native            网页缓存原生方法（原型 patch 失效场景）
[测试] 标签数 21 → 21
通过 7/7
```

**这是 Safari 方案成立与否的关键实验**：证明"页面内 window 捕获阶段 + stopImmediatePropagation
+ stopPropagation + setData + preventDefault"能压过网页的所有常见劫持方式。

### 过程中踩到的三个坑（都已修）

1. **自己的 `preventDefault` 被自己的护栏拦下**
   → 事件从未被取消，浏览器提交原始选区。修法：patch 里加 `internalCall` 标志区分"自己调用/网页调用"。
2. **WebKit 的 `clipboardData` 不是 `DataTransfer` 实例**
   → patch `DataTransfer.prototype.setData` 对它**完全无效**（日志里根本没有 `guard:blocked-setData`），
   网页在 document 阶段仍能覆盖我们的写入。
   修法：改用事件层面阻断 —— `stopImmediatePropagation()`（挡同 target 后注册监听器）
   + `stopPropagation()`（挡继续向 document/target 传播）→ 网页的 document 监听器根本不执行。
3. **AppleScript 读文件按系统本地编码解码**
   → 本机区域设置是中文/GBK，注入的 JS 里的中文变成乱码（`人` → `浜�`），映射静默失效。
   修法：注入内容一律 ASCII 化（非 ASCII 字符转 `\uXXXX`）。
