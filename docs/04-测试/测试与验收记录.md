### 真实故障复盘:「复制只修好一半」(2026-10-21)

**现象**:学习通测验页复制,前半句是明文、后半句仍是密文:

```
【单选题】固定导轨的安装扣最先在()的安装上使用。            ← 修好了
【判断题】一旦有人提出无抲宣告请求,专利局抸者法抶就必曳抷理。  ← 抲抸抶曳抷 没修
```

**排查过程**(每一步都有实测):

| 假设 | 验证方式 | 结果 |
| --- | --- | --- |
| 映射表里没有这些字 | 导出映射表全表 | ❌ 表里**有**(抲→效、抸→或、抶→院、曳→须、抷→审) |
| 作用域有多个、查错了表 | 逐 frame 导出作用域与映射 | ❌ 全页**只有一个** `@font-face`、一个作用域、19 条映射 |
| 字体被换了、指纹变了 | 对比 @font-face 与作用域指纹 | ❌ 指纹稳定(`font-cxsecret#datalzv4nl`) |
| **作用域缓存没赶上选区** | 清空采集缓存后立刻复制 | ✅ **命中** —— 不修的正是"没被采集过的新密文字" |

**根因**:映射表按字体整份下发(是对的),但"这个字属于哪个字体作用域"
存在**采集缓存**里,采集比复制慢一拍 → 新选区里的密文字查表落空 → 原样进剪贴板。

**修复**:守卫 v6 —— 复制时**当场**按当前选区从 DOM 现算作用域(ADR-0005)。

**红/绿对照**(仓库自带闭环测试 `loop.cjs` 阶段3,选一段从未采集过的新密文字并立即复制):

| 守卫 | 剪贴板 | 结论 |
| --- | --- | --- |
| v5(旧) | `闰余成岁律吕调阳云腾致雨露结为霜金生丽水玉出昆冈` | ✖ 原样密文 |
| v6(新) | `推理应用场景需求用户体验设计开发测试部署运维监控` | ✔ 全部还原 |

### 通用性专项(2026-10-21):修法必须对"没给过的场景"也成立

#### 发现并修掉的两个"只在那几道题上成立"的问题

| # | 问题 | 旧行为 | 新行为 | 用例 |
| --- | --- | --- | --- | --- |
| 1 | 查表按**字符身份**(一个字只对应一个作用域) | 同一个字出现在密文与普通两种作用域时,普通那处被一起改掉 → **写出错字**(实测「人人」) | 按**出现位置**(逐个文本节点)判定,各查各的表 | `generality.cjs` s1/s2 |
| 2 | 参考库只含 GB2312 | 库里缺的生僻字被认成形近的错字 → **写出错字**(燚→焱、垚→寺、鿕→鲋、㶿→饽) | 参考库换 GBK 全集(gzip 9.7MB),真答案在库里;认不出的被闸门挡住 | `tools/lab/probe-missing-char.cjs` |

**为什么第 2 条不能用"提高阈值"糊过去**:真实字体的逐字分数最低只有 0.8881,
而缺字错配的分数是 0.81~0.90 —— 区间重叠,阈值分不开"真匹配"与"缺字错配"。

#### 顺带修好的一个对齐坑

复制时要按"片段"替换,但浏览器的 `selection.toString()` 是**渲染后的文本**(空白按 CSS 折叠),
文本节点原文里却带着制表符、缩进换行 → 直接比对必然对不上(实测整页选中时第一段就断)。
改成**只比对非空白字符**、输出仍用浏览器那份文本(排版不变)后解决。

### 为什么「坉」判不出来(实测,不是猜)

| 假设 | 验证 | 结论 |
| --- | --- | --- |
| 参考库里没有「略」 | 查 GBK 库 | ❌ 有 |
| 4bit 量化导致 | 全精度重算 | ❌ 0.1288 vs 0.1276,几乎一样 |
| 分辨率不够 | 48/64/96 三档 | ❌ margin 0.0156/0.0137/0.0151,基本不变 |
| 粗筛筛掉了正确答案 | 查粗筛排名 | ❌ 排第 1、2 名 |
| margin 闸门太严 | 读引擎判定 | ✅ 命中 |

顺带挖出两个真 bug:

1. **「常用字优先」这个判定从来没生效过**:`COMMON_SET` 存的是**字符串**,
   候选的 codepoint 是**数字** → `has()` 永远 false → 从写下来那天起就是空转的。
2. **margin 闸门把生僻字也当成了同样说得通的竞争者**:
   格(木各)/挌(扌各)/恪(忄各)像素上几乎一样(0.8496 vs 0.8472),
   但字频分得开 → 改成**给常用字先验加分并参与 margin 计算**。
   修完:圻→**格** ✓ 还原了。

「坉」仍然判不出来,因为站点重绘后的「略」像素**离「赂」更近**(0.1007 vs 0.1162),
**像素里没有答案**,只能靠语境("战X管理能力"→战略),本版未做 →
系统**保守不改**(留密文码位,不写错字)。

### 换题回归(新增,2026-10-21)

用户每换一套题就换一套加密字体。这条测试专门盯这件事:
**同一个标签里来回换字体(A→B→A→B)**,两套字体码位相同、画成不同的字
(旧映射泄漏的话答案会明确错掉)。

| 场景 | 结果 |
| --- | --- |
| 第 1 题(A) | ✔ |
| 换题 A→B | ✔ |
| 换题 B→A | ✔ |
| 连续换题 A→B→A→B | ✔ 3/3 |

**这条测试第一次跑就抓出两个真 bug**(见 ADR-0009):
① 预热与选区用了不同阈值 → 换题后"选中就立刻复制"必然缺字
② 站点重绘笔画更细 → 灰度距离偏向笔画少的字(「略」被认成「赂」)

### 根因(ADR-0010)要点

| 观测 | 数值 |
| --- | --- |
| 失败字在不在库里 | **都在**(参考库是 GBK 全集 21517 字) |
| 墨量比(站点 vs 参考) | **0.880**,25 个码位全在 0.80~0.91 → 系统性变细 |
| 宽比/高比、重心偏移 | 1.00/0.98、≈0px → 几何完全一致 |
| 病根 A | 像素距离偏爱"笔画少"的字 → 「略」输给「赂」 |
| 病根 B | 库里有只差一笔的孪生字(国/囯)→ margin 0.0100 → 被闸门挡 |

**教训**:通用不是多写几个用例,而是找到那个**可被度量解释的系统性差异**。
前面几次都在阈值和规则层面打转,真正根因是**度量的量纲错了**。

### 换题后的"映射就绪窗口"(2026-10-21 晚)

复现:同标签内换字体 → 立刻复制。

| 时刻 | 剪贴板 |
| --- | --- |
| 换题后立刻 | **原始密文**（"天地玄黄宇宙洪荒日月盈昃…"） |
| 换题后第 1 轮 | ✔ 正确（1956ms） |

**=> "换题就失败"的机制:不是识别不准,是新字体的映射还没建好。**
修:① 预热与选区统一阈值(之前预热 0.88 / 选区 0.8,预热那张表少几条)
② 给"带混淆字体的标签"单开快轮询(~200ms)→ 就绪时间 2.0s → **0.5s**

### 明文到底在不在浏览器里(实测)

穷举搜过:DOM / 所有属性 / `<script>` / 输入框值 / 注释 / `window` 全局 → **没有明文**。
同源接口响应里也是密文(`aria-label='A 企嵻嵽嵼选择'`)。
**=> 混淆是服务端做的,明文从没到过浏览器**;页面里"正确"的只有字体里的字形和屏幕像素,
而像素路径拿到的形状信息与字形路径完全相同 → 反推字形是唯一可行路径。

### 验收判定自身的坑(已修)

`tools/verify/verify-app-e2e.cjs` 原先用 Unicode 区段(U+3400–U+4DBF)猜"密文字",
而学习通真实密文字在 **U+62xx / U+66xx / U+78xx**(抲 U+62B2、抸 U+62B8、曳 U+66F3)
→ **完全落在那个区段之外 → 永远判定为 0 → 假通过**。
现改为按**页面里实际下发的映射表**判定(表里的键 = 被混淆的码位),
并追加"明文片段命中"作为独立交叉验证。

### 换题后第 1 次成功、第 2 次复制出密文 —— 页面侧三个根因(ADR-0017)

**现象**:用户复测「换一题之后,第 1 次复制成功,第 2 次复制失败(复制出来是密文)」。

**和上一条记录不是同一回事**:上一条是"iframe 桥的 frame 名单过期",
这一条是**页面侧守卫(`packages/browser-adapters/shared/src/page-guard.ts`)的三个根因** ——
两个仓库共用同一份源码,所以**两条线同时中招**。

| # | 根因 | 地面真相 | 修法(两边同源) |
| --- | --- | --- | --- |
| 1 | 「送到了就不重报」**用错了账本** | 判据拿 `mappings[scopeKey]`(回答"页面能不能修复复制"),不是"App 知不知道" → **App 重启后**页面仍留着上一任 App 的映射 → 页面以为"不用报" → App 永远学不到这个作用域 → 快通道是瞎的 | 两本账分开:新增 `deliveredAt`(App 知不知道,resync **清它**)、`mappings`(页面能不能修,resync **不动**) |
| 2 | 预热扫描触发条件太窄 | 站点顺序是"先注入 @font-face → 再渲染题目文字" → 第一次扫描签名已是新字体但扫到 **0** 个作用域 → 之后签名不再变 → **永远不再重扫** | 触发条件加上"DOM 变了"(MutationObserver 只置 `domDirty` 标志位,扫描仍每轮最多一次) |
| 3 | 字体指纹用**取样哈希** | 混淆字体"结构相同、字形不同" → 取样点可能落在两份字体**相同**的字节上 → 撞车 → 旧映射套新字体 → 复制出**错的字**(违反"宁可留错字,绝不写错字") | 改成**整份哈希**(FNV-1a,18KB ≈0.1ms);真机上同一份字体:取样 `datagi2tog` → 整份 `data2cozfw` |

> 顺带修掉一条**致盲**的规则:"报过但没收到映射 → 冷却 3 秒再试"。
> 报告可能半路丢掉,而 App 一次都没收到 → 这 3 秒里 App 根本不知道这个作用域存在。

> 这条改动让本仓库的 `iframe-case` 闭环用例**从红变绿**。

### 每轮重报、日志刷屏、旧版守卫换不掉(ADR-0018)

**现象**:共用守卫升级之后复查时看到三件不对的事:

1. 页面**每 200ms 重报一遍作用域**,其中一半是**永远建不出映射**的普通字体;

## 快捷键改成 ⌃S / ⌃D + latch(2026-10-23)

- 用户要求(本仓库 ADR-0013 / Tauri 仓库 ADR-0024):
  > 「不要 shift 了,直接 ctrl 吧 …… 触发之后 Ctrl 加 D 整个按键就不再会继续影响它了,
  > 除非下一次重新按住 Ctrl,再点击相应的字母」
- 改了什么:
  - **键位**:`globalShortcut.register('Ctrl+S' / 'Ctrl+D')`
    (⌃⇧A → **⌃S**、⌃⇧D → **⌃D**);界面里绑的那两处也一并改成 `Ctrl+S` / `Ctrl+D`。
  - **latch**(与 Tauri 侧**同一份规则**):触发 ⇒ 锁;
    **Control 松开** ⇒ 解锁;Control **按下**不能无条件解锁
    (迟到的按下事件会解除 latch ⇒ 按住 Ctrl 连按会连着触发 ⇒ 回放乱点)。
  - **怎么知道 Control 松开了**:另开一个 **ListenOnly 会话级 tap**
    (`mac-coregraphics` 新增 `watchControlKey`),
    只听 `kCGEventFlagsChanged`,把 Control 的边沿喂给 latch 状态机。
    - ListenOnly **不需要「辅助功能」权限** ⇒ ad-hoc 签名的 Electron 也能用;
    - 吞键仍然交给系统热键做(系统替你吞 ⇒ 不漏键、不需要权限)。
  - 状态机抽成 `shortcut-latch.cjs`(纯函数,与 `playback-guard.cjs` 同一个套路),
    才能进 CI 测。
- 回归:
  - `node --test tools/verify/verify-shortcut-latch.cjs` → ✅ **4/4**,
    已接进 CI 的「跑不过就不发包」门禁(在 `Build .app` 之前);
  - `node --test tools/verify/verify-playback-guard.cjs` → ✅ 4/4(未受影响);
  - 原生模块(`npm run build:native`)编译通过;
    `watchControlKey` 冒烟返回 `true`(只读 tap 建起来了);
  - **变异自检**(base 先绿 → 变体被抓住 → 还原复绿):
    | 变体 | 被哪条抓住 |
    | --- | --- |
    | M1:Control 按下时**不看 blocked**就武装 | `迟到的「Control 按下」不能解除 latch` |
    | M2:触发后**不记 blocked** | 同上 |
- **诚实的边界**:
  - **Windows 线没有 latch**(`win-input` 没有这个只读监听)—— 平台差异;
  - **`win` 分支本轮没动** ⇒ Windows 包仍是 ⌃⇧A / ⌃⇧D;
  - Electron 若拿不到只读监听 ⇒ `latch=false` **如实降级**(打 warn),
    **不假装 latch 生效**;
  - 锁着的时候,系统热键照样吞掉按键(不往前台漏),只是**不执行动作**;
  - 自检**不发任何系统级键盘/鼠标事件** —— 全是进程内纯函数单测。

## 「默认执行」没功能 —— 缺「辅助功能」权限,且失败是静默的(2026-10-24)

- 用户报:「现版本的 electron 版本根本就不能用,**至少默认执行是没有功能的**」。
- 根因链:
  1. 发合成点击/按键(`CGEventPost`)需要 macOS 的「辅助功能」权限;
  2. 没有权限时系统**静默丢弃**事件 —— 命令返回成功、屏幕上什么都没发生;
  3. Electron 线**没有权限闸门** ⇒ `executed` 照加 ⇒ 界面显示「开始执行」
     ⇒ **失败完全不可见**;
  4. App 还是 **ad-hoc 签名**(`TeamIdentifier=not set`)⇒ 授权留不住;
  5. 界面层**缺了「辅助功能」小问号**(Tauri 有、Electron 没有)⇒
     用户根本不知道有这回事。
- 修法(与 Tauri 版逐项对齐):
  | 项 | 做法 |
  | --- | --- |
  | 原生层 | 新增 `accessibilityTrusted` / `requestAccessibility`;`mouseClick`/`sendText`/`sendKey` 前加**权限闸门**,没权限**报错** |
  | 主进程 | `native:getStatus` 带 `accessibilityTrusted`;`native:requestAccessibility`;`window:openAccessibilitySettings`;回放/键入**入口前置检查** |
  | 计数口径 | 发不出去**不计入 executed**、记**第一个** error、**继续往下走**(与 Tauri 收拢) |
  | 界面 | 第 4 页「辅助功能」小问号与 Tauri **逐字一致**;`App.jsx` 传三个 props |
  | 签名 | `after-pack.cjs` 优先用钥匙串里的**真证书**,签不了才退回 ad-hoc |
  | 启动 | 没有权限时**主动向系统申请**一次(用户在弹窗里点「允许」) |
- 回归:
  - 原生层冒烟(无权限进程):`mouseClick` / `sendText` **抛错**,带人话指引
    ⇒ 不再假装成功;`accessibilityTrusted` 返回 `false` ✓;
  - UI/快捷键/回放 **10/10**;打包自检全绿(含「包内所有相对 require 都能解析」);
  - 运行时日志:`[shortcut] Ctrl+S=true Ctrl+D=true latch=true` +
    `[accessibility] 没有「辅助功能」权限,已向系统申请`;
  - 已装 App 签名:`TeamIdentifier=769LN7AY28`(与 Tauri 版同一张证书)。
- **诚实的边界**:
  - **授权这一步必须用户手动点** —— 系统不提供程序化授权接口。
    Electron 与 Tauri 的 bundle ID 不同 ⇒ **不共用**同一份授权。
  - **CI 产出的包仍是 ad-hoc 签名**(CI 机器上没有证书)⇒ 从 Release 下载的包
    授权照样留不住。要彻底解决需要 Developer ID 证书(付费团队)。
- 详见 ADR-0015。

## CI 随机翻红:换页动画的采样窗口和动画时长一样长(2026-10-24)
- **抖动还是回归?用重跑定性**:同一个提交 `fc1fd6c` 的**重跑**
  (run `40052219168`)→ **success** —— 同一份代码上一轮红、这一轮绿 ⇒
  确属**采样窗口的时序抖动**,不是代码回归。

- **现象**:红的是 **Tauri 仓库**的 CI(提交 `fc1fd6c`,**只改了两个文档**)——
  `verify-panel-transition.cjs` 的「改成 auto 之后横向溢出没发生」。
  上一次绿灯的提交与它之间**代码完全相同**;
  本仓库跑的是**字节相同**的同一份测试文件、几分钟前刚绿过 ⇒ 排除代码差异。
- **根因**:换页动画时长是 `0.4s`(`Stepper.jsx` 的 `transition={{ duration: 0.4 }}`),
  而判别性检查只采样 `10×40ms = 400ms` —— **采样窗口和动画时长完全相等**。
  「点击 → React 重渲染 → 动画起跑」要再花掉一点时间,
  机器一慢(动画起跑晚几十毫秒),产生横向溢出那一段就被整个错过 ⇒
  把「**采样窗口没罩住**」误判成「**前提不成立**」。
- **修法**(`watchTransition()`,两个仓库同一份):
  - 采样不再固定 400ms,而是**采到「已经看到溢出 **且** 动画确实停了」**为止(上限 4s);
  - 判别性检查那一段**往返最多试 3 轮**(1 → 2),3 轮都没有溢出才算红。
- **判据没变**:动画真的跑了、真的横向溢出了,才算通过 —— 只是不再靠运气。
- **变异自检**(改构建产物 `dist/`,验完还原,产物是 gitignore 的,仓库不脏):

  | 变异 | 期望 | 实际抓住它的断言 |
  | --- | --- | --- |
  | M1 退场页不再横向滑动(`x:'50%'` → `'0%'`) | 红 | `切换过程中没有出现横向溢出 —— 说明动画没真的在跑,这条用例等于没测到东西` |
  | M2 `overflow-x` 改回 `visible`(还原用户报的「下面那条滑条」) | 红 | `内容容器横向必须是 hidden,实际 auto` |

  ⇒ **用例对它本来要抓的缺陷仍然有判别力**,不是把门槛放低换绿灯。
