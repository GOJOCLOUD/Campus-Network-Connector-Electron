# 打包与发布

## 构建链路

```bash
npm run build            # 前端 vite 构建 → dist/
npm run build:native     # clang++ 编译原生模块 → mac-coregraphics/build/Release/*.node
npm run build:vendor     # 从 packages/ 构建注入脚本与参考库 → vendor/（进安装包）
npx electron-builder --mac dir --arm64    # → release/mac-arm64/模拟输入.app
npx electron-builder --win nsis --x64     # → release/*.exe
```

`npm run dist:mac:arm64` = 上面前四步的组合（macOS 出 **目录形态** .app，
不再出 dmg —— 交付统一用 zip，dmg 只是同体积的另一层壳）。

> `npm run build:vendor` 已在打包脚本里串好：参考库 `.crdb` 是构建产物，
> 缺了会就地重建（约 5 秒，与仓库里那份字节级一致）。

## 产物校验(**必做**)

```bash
node tools/verify/verify-package.cjs [app路径]
```

检查:原生模块是否解包且可加载、Safari 修复运行时文件是否齐全、**文档/测试脚本有没有混进安装包**。

> 历史上出过两次事故,都是这一步能提前发现的:
> ① 原生模块被塞进 asar → 模拟输入整组功能静默失效
> ② 守卫日志绕过上限 → 页面日志无限增长

## 打包白名单

`package.json → build.files` 是**白名单**(只打列出的),同时显式排除:

```json
"!src/features/**/test/**/*",   // 功能自测脚本
"!docs/**/*",                    // 文档系统
"!tools/**/*",                   // 开发脚本
"!**/*.md"                       // 零散 markdown
```

`node_modules` 由 electron-builder 自动处理。

## 发布检查单

- [ ] `npm test` 全绿(串行)
- [ ] `node tools/verify/verify-package.cjs` 全绿
- [ ] macOS .app 目录 / Windows NSIS 都产出,体积与上一版相当
- [ ] 桌面上的两个包:mac zip 与 Windows zip **分开放**(但每个包里含**两条线**的产物)
- [ ] 覆盖安装时注意 `app.asar.unpacked` 目录要一起被替换(只换 asar 会导致原生模块失效)

## 桌面交付

```bash
node tools/lab/package-deliverables.cjs
# → ~/Desktop/模拟输入-mac-arm64.zip        (内含 模拟输入.app + 模拟输入-Tauri.app + 安装说明)
# → ~/Desktop/模拟输入-Windows-全部.zip      (内含 两个安装程序 + browser-extension/ + 安装说明)
```

**两条线进同一个包**（Electron 版与 Tauri 版，功能等同、都是正式版）：
用户一次解压就拿到全部，不用去猜「哪个才是那个」。
mac 与 Windows **仍然分开放**（用户群不同、装法也不同）。


**Windows 交付包还带一个 `browser-extension/` 文件夹**(2026-10-25 起):
Windows 上的「把密文还原成明文」由 Chrome/Edge 扩展提供(桌面接管不了浏览器),
而扩展**必须**随产品一起交付 —— 之前扩展一直都在仓库里、却**没进任何安装包**,
所以 Windows 上那条能力实际等于零。
出包前脚本会**对着 zip 内容**自检:扩展的 5 个文件 + README 缺一就**不出包**。
CI 的 release 也会额外发一个 `browser-extension-chromium.zip` 附件
(只下了 `.exe` 的用户从那里拿)。

脚本还会把**被取代的旧交付物**（`模拟输入-win-x64-安装包.zip`）和桌面上的
`*.dmg` 移进**可恢复回收站**（不是永久删除）。

**Windows 产物从 CI 的 release 取**（本机不打包 Windows —— 交叉编译出来的包
不带原生模块）：脚本自动挑最新的 `win-tauri-*` / `win-*` release；
要指定就设环境变量 `WIN_TAURI_TAG` / `WIN_ELECTRON_TAG`。
（release 上的**附件文件名**可能丢掉中文前缀 —— 那是 NSIS 在 Windows runner
上的编码问题，打进交付包时脚本会规整成 ASCII 名；**安装程序内部的产品名是好的**。）

**交付统一用 zip**：体积与 dmg 相同，但双击即解压、不需要挂载镜像，
Windows 侧也不用再套一层。zip 内部文件名对 Windows 包用 ASCII
（中文名在 Windows 资源管理器里会变问号）；mac 包保留中文名
（ditto / unzip 解出来都正常）。

> ⚠️ **mac 包必须用 `zip -r -y` 打包**：`-y` 让**符号链接**被存成符号链接。
> Electron 的 framework 里有 **14 个**符号链接
> （`Electron Framework.framework/Versions/Current` 等），
> 不加 `-y` 会被存成普通文件副本 → 解压出来的 App 起不来。
>
> ⚠️ **包建好之后不要再用 `zip` 改写它**：`zip` 不认 macOS 的 bundle 语义，
> 改写会把 `.app` 压成**一个平铺的文件**（解出来不是能双击的 App）。
> 要加说明文件，就**先把所有东西放进暂存目录，再一次性打包**。
>
> （这两条都是 2026-10-23 打包时真踩到的：脚本把 ditto 的目标写成了
> `stage/xxx.app`，每个「.app」其实是个 zip 文件，再被 `zip -r` 套进去 →
> 交付包解压出来是两个平铺文件。）

> CI（GitHub Actions）现在发布的也是 **zip**（`gh release` 附件），
> 不是 DMG —— 那是另一条链路，不受这里的桌面交付规则影响。
